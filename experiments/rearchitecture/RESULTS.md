# 垂直切片验证记录

- 记录日期：2026-08-29
- 当前轮次：第一轮完成；Astro 第二轮状态/交互岛组与第三轮首帧/连续帧组完成
- 生产影响：无；所有实现和测试均位于隔离实验目录

## 结论

Astro 候选通过了本轮全部硬门槛，进入下一轮验证。Qwik 候选在真实 SPA 导航中下载包含完整文章正文的路由 JavaScript，违反“正文不得以同阶内容再次进入 JavaScript/JSON”的硬门槛，因此不再作为默认候选。

这不是只检查构建目录得到的推断：Playwright 从博客列表执行站内导航并捕获实际响应，正文探针出现在下载的 Qwik 路由脚本中。给正文包裹 `RenderOnce` 后结果不变；该组件限制后续渲染，但不能让客户端在没有路由 JSX 的情况下渲染目标页。

Qwik 可以改用原生 `<a>` 进行完整文档导航来避免下载目标路由脚本，但这会同时放弃同构建导航中的持久 SiteShell 和客户端状态连续性，转而违反另一项硬门槛。当前没有发现同时满足两项约束的 Qwik City SSG 路线。

本轮测试发现并修复了五类真实架构错误：

1. 目标 HTML 抓取完成后、字体等待期间，用户仍可切换主题。旧实现过早复制偏好，会在提交时覆盖用户的新选择；偏好复制现位于 `astro:before-swap` 最终提交边界。
2. 浏览器遍历时，Astro 先应用原生历史滚动，再触发 `astro:after-swap`。旧监听器会把框架恢复产生的滚动误记为用户输入并覆盖目标历史项；恢复事务现从 `astro:before-preparation` 的 `traverse` 开始，期间禁止写账本。
3. `content-visibility: auto` 与估算高度使同一篇 72 节文章在离场和返回时相差 518 px，浏览器滚动锚定把目标 1120 px 改到 947 px。静态正文已移除这项不确定几何优化；同一路径双历史项连续 5 次复测全部通过。
4. 动态导入失败会永久停在“正在加载”并产生未处理拒绝。现在由独立生命周期控制器统一去重、分类失败并在销毁后抑制迟到回调，Svelte 组件只负责状态呈现。
5. 跨代原生导航会建立真实的跨文档历史边界。测试最初错误地要求从构建 B 后退到部署前历史项时仍保留 B 的外壳节点；网络 trace 证明该遍历必然是新的 `document` 请求，ClientRouter 无法把已经发生的跨文档遍历改写成同文档 swap。现在同代历史仍保持外壳，跨旧边界则由新代完整文档加载，并在 body 解析完成后从原历史项恢复主滚动和嵌套滚动。

字体协调器另有 ready、degraded、timeout、unsupported、not-required 和 AbortError 的 6 类单元测试。空 `required-fonts` 曾被解析成无效权重 `0`，现只接受大于 0 的有限权重。测试专用的字体/构建结果 dataset 已从候选 bundle 移除。

## Astro 第三轮：首帧根因与修复

连续帧证据确认，故障不是“字体缓存偶尔失效”，也不是正文必须等待水合。旧候选的生成 HTML 在首屏关键静态结构完成前执行了 Astro/Svelte SiteShell island bootstrap；CSS 如果在这次 parser pause 中完成，Chromium 就可能提交只有部分静态 DOM 的真实中间帧。字体冷加载会放大这个窗口，但不是根因。

修复没有改变页面视觉、控件或导航交互形态：

1. SiteShell 改为 Astro 静态 HTML，并由一个紧邻外壳、委托事件的自包含 TypeScript 控制器增强；按钮在长正文继续解析前即可用，列表页不再产生任何 `astro-island`。
2. head 使用 `rel=expect` 指向精确的 `#initial-frame-ready`：列表只等待前三张卡，文章只等待文章头、完整目录和第一节，不把整篇 72 节正文作为 render boundary。
3. JavaScript 可用时，边界内协调脚本复用同一字体加载器、history codec 和滚动应用函数；字体与滚动提交后才释放边界，任意失败或 1.8 秒超时均 fail-open。
4. 交互图仍是独立 Svelte island，并且位于首帧边界之后；重型模块继续只在用户明确操作后加载。

新增证据如下：

| 验证项                                | 结果 | 关键断言                                                                 |
| ------------------------------------- | ---- | ------------------------------------------------------------------------ |
| 冷启动文档、字体网络延迟              | 通过 | marker 不存在的解析帧不具备呈现资格；首个可呈现帧结构完整且字体已加载    |
| 已呈现页面、字体协调延迟              | 通过 | 进度可见期间旧列表保持完整；释放协调器后目标文章只提交一次               |

`rel=expect` 当前只由 Chromium 自动化证明。Firefox/Safari 会在不支持时退化为完整静态 HTML 的渐进解析，但这还不能证明它们满足“首个可见帧即终态”；该项保持为生产迁移门槛。

当前全量结果为：Astro 22 条常规浏览器场景和 3 条独立双构建场景全部通过；Qwik 3 条共享正向场景通过，正文重复交付门禁继续复现为预期失败，18 条 Astro 专属场景跳过。纯 TypeScript 单元测试 27 条全部通过，行为文档结构测试 4 条全部通过。

## 构建证据

固定 fixture 包含 72 个正文 section。原始、gzip 和 Brotli 数据由 `npm run measure` 使用相同参数生成，完整机器可读结果见 `reports/build-metrics.json`。

| 指标（字节）                 |  Astro |    Qwik |
| ---------------------------- | -----: | ------: |
| 文章 HTML 原始               | 98,843 | 108,171 |
| 文章 HTML Brotli             |  6,085 |   9,526 |
| 全部客户端 JS 原始           | 54,039 | 185,631 |
| 全部客户端 JS Brotli         | 18,956 |  41,692 |
| 含正文探针的外部资产         |      0 |       1 |
| 含正文的 Qwik 路由 JS 原始   |      — |  81,397 |
| 含正文的 Qwik 路由 JS Brotli |      — |     988 |

fixture 为了稳定复现使用大量结构相同的中文段落，因此 Qwik 正文块的压缩后体积异常小；这个数字不能外推真实文章的传输成本。硬门槛失败依据是正文所有权和重复交付，而不是用这一压缩数字夸大性能损失。下一轮性能结论必须再使用真实文章语料校准。

与上一轮 Astro 产物相比，生成式首帧/壳层控制器使文章 HTML 增加 6,908 B 原始 / 1,803 B Brotli；移除 Svelte SiteShell island 使全部客户端 JS 减少 2,526 B 原始 / 1,142 B Brotli。这个取舍把首帧恢复和早期控件增强放回每个可独立加载的完整文档，同时避免为静态 Header 启动组件运行时。

## 工程边界

- 两个候选不共享浏览器运行时代码，只共享内容 fixture、视觉 token 和测试。
- DOM 身份探针已从候选 bundle 中删除，测试直接比较节点引用。
- SiteShell 是静态 Astro HTML；控制器使用公开 DOM 语义和委托监听，不建立全站 Svelte 根或第二套事件总线。
- 初始文档只把稳定首帧所需的有限区域设为 render boundary；完整长正文继续在其后静态解析。
- 文章目录在 DOM 中提前解析，但移动端通过明确单列 grid 保持“文章头 → 正文 → 目录”的既有视觉顺序，并有独立浏览器断言。
- Astro 的主题复制发生在目标文档 swap 前；没有 swap 后补帧。
- 页面根滚动不再全局启用 `smooth`；状态恢复是瞬时操作，目录锚点仍保留浏览器原生无脚本行为。
- 静态正文不使用估算高度的 `content-visibility`；真实文章上的布局成本仍需在性能轮校准。
- 主题动画通过注册颜色 token 插值，不向所有组件注入通用 `transition`。
- 交互岛异步所有权位于纯 TypeScript 控制器，组件销毁只调用一个幂等 `dispose()`。
- 构建 ID 同时编译进运行时常量和 HTML meta；只有运行时、当前文档和目标文档三方一致时才允许客户端 swap。未知身份与不一致身份都按部署边界处理。
- 双构建测试给 A/B 资产使用不同目录命名空间，并检查边界之后的所有带代际响应；生产默认资产目录仍是 `_astro`，测试命名空间不进入生产配置。
- 版本门使用 Astro 7.1.6 中可取消的 `astro:before-preparation` 事件：先运行官方公开的 `loader()`，再取消不安全提交。官方文档公开了 loader 包装点，但未把取消后的 `location.href` 细节列为稳定契约，因此 Astro 升级必须运行双构建集成测试。
- Qwik 的 URL 会早于 `RouterOutlet` 提交更新；其 POC 仅在公开的 `isNavigating=false` 后恢复嵌套滚动，连续 5 次复测通过。
- Qwik 官方构建流程当前还需要显式补充其 CLI 运行时使用但未声明的 `ignore` 包；这记为工具链风险，不是本轮淘汰依据。
