# 设计验收与实施门禁

## 设计确认门禁

进入实现前必须确认：

- [x] 文章索引不设置可见 H1 或说明区；
- [ ] 信息架构图；
- [ ] 统一面包屑；
- [ ] 当前版本、历史版本和 Diff 的关系；
- [ ] 桌面低保真线框；
- [ ] 移动低保真线框；
- [ ] 高保真原型；
- [ ] 视觉 Token；
- [ ] 删除清单；
- [ ] 全部状态矩阵。

任一项未确认，不开始修改 `src/`。

## 实施顺序

1. 建立统一 `ArticleBreadcrumb`。
2. 建立统一文章页面外框和 12 列网格。
3. 迁移当前文章和固定版本。
4. 实现自由双版本选择和 Diff。
5. 将文章索引收敛为工具条与文章列表。
6. 删除旧返回链接和相邻文章逻辑。
7. 完成标签和分页状态。
8. 完成目录与版本工具响应式状态。
9. 进行视觉回归和键盘验收。

不得在同一步同时改变内容模型和视觉设计。

## 页面验收

### 文章索引

- [ ] 不渲染独立 H1 或功能说明区；
- [ ] 首个可见区域仅包含文章数量与标签；
- [ ] 页面没有第二套列表标题；
- [ ] 全宽空间有明确列关系；
- [ ] 标签全部可进入标签页；
- [ ] 分页只在需要时出现；
- [ ] 没有年份归档。

### 普通文章

- [ ] DOM 中没有版本工具；
- [ ] 面包屑位置与多版本文章一致；
- [ ] 标题、摘要、元数据和正文左边界一致；
- [ ] 没有相邻文章区域。

### 当前多版本文章

- [ ] 默认 URL 显示最新版；
- [ ] 版本工具完整但不改变标题位置；
- [ ] 所有公开版本都能从版本选择器到达；
- [ ] 比较表单可以选择任意两个不同版本。

### 历史版本

- [ ] 面包屑最后一级是版本号；
- [ ] 页面明确写出“历史版本”；
- [ ] 当前版本号和当前版本入口可见；
- [ ] 旧正文不被覆盖；
- [ ] 不使用“返回当前文章”作为顶部导航。

### Diff

- [ ] 起始和目标版本清楚；
- [ ] 用户可以重新选择任意两个不同版本；
- [ ] 相同版本不能提交；
- [ ] 反向选择规范化为稳定 URL；
- [ ] 可分别阅读两个端点；
- [ ] 新增与删除不仅依赖颜色；
- [ ] 面包屑父级是当前文章；
- [ ] 没有额外返回按钮。

## 响应式验收

每个页面至少保存以下截图：

```text
360 × 800
390 × 844
768 × 1024
1024 × 900
1440 × 1200
```

检查：

- [ ] 无横向滚动；
- [ ] 面包屑不随机换行；
- [ ] 版本工具不形成四个同权重大按钮；
- [ ] 目录状态正确；
- [ ] 长标题不遮挡；
- [ ] 标签能正确换行；
- [ ] 焦点可见。

## 数据压力测试

- [ ] 0 篇、1 篇、8 篇、9 篇和 100 篇文章；
- [ ] 无标签、1 个标签和 10 个标签；
- [ ] 单版本、2 个版本和 12 个版本；
- [ ] 45 个汉字标题；
- [ ] 200 字版本摘要；
- [ ] 超长代码行和宽表格；
- [ ] 无目录和 30 项目录；
- [ ] 大型 Diff。

## 完成定义

以下条件同时满足才算完成：

1. Astro 类型检查和构建通过；
2. 全部内部链接存在；
3. 生产页面与批准的原型逐屏对照；
4. 响应式截图通过评审；
5. 键盘、焦点和减少动态效果通过；
6. 旧返回链接和相邻文章逻辑不存在；
7. 没有因 Demo 内容而硬编码页面结构；
8. 用户批准最终视觉结果。
