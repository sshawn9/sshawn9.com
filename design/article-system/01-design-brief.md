# 产品与设计简报

## 背景

站点同时承担个人品牌、项目展示和长期内容输出。文章系统需要支持普通 Markdown 文章，也需要在发生实质修订时保留每个完整历史快照。

已有内容模型基本成立，但页面实现缺少统一的信息架构和版式设计，导致：

- Demo 说明被错误提升为页面主标题；
- 文章、历史版本和 Diff 使用不同的布局起点；
- “返回文章列表”“返回当前文章”在不同位置跳动；
- 版本能力存在，但其导航关系没有被完整定义；
- 实现先于设计，页面只能局部修补。

## 设计目标

1. 让访客在任意文章相关页面都能立即判断当前位置。
2. 让普通文章保持普通，不暴露无关的版本概念。
3. 让历史版本清楚表达“这是旧快照”，同时不打断正文阅读。
4. 让版本选择和 Diff 成为文章的附属能力，而不是独立内容栏目。
5. 让列表、标签和分页支持长期增长。
6. 保留站点的网格、光效、深色模式和品牌感，同时建立严格排版秩序。
7. 所有关键状态在实现前拥有桌面和移动端设计。

## 非目标

- 不增加评论、点赞、阅读量、Newsletter 或社交分享。
- 不增加年份归档。
- 不增加上一篇/下一篇或相关推荐。
- 不把多版本文章包装成站点卖点。
- 不在本轮决定用户最终的个人品牌文案。
- 不在设计确认前修改生产代码。

## 主要使用情境

### 浏览文章

访客从全局导航进入文章索引，按发布时间浏览，通过标签缩小范围，必要时翻页。

### 阅读普通文章

访客进入正文，看到文章身份、摘要、发布时间、标签和目录；页面完全没有版本控件。

### 阅读多版本文章的当前版本

访客默认进入当前版本，可选择任意公开版本阅读，也可以选择任意两个版本比较差异。

### 阅读历史版本

访客通过版本选择器进入旧版本。页面明确说明版本号、发布时间和当前最新版，并提供“阅读当前版本”和“比较差异”操作。

## 成功标准

- 页面标题不再承担 Demo 组件说明。
- 六类页面的面包屑在相同横向和纵向位置。
- 从任何历史版本都能在一次操作内到达当前文章或双版本比较。
- 普通文章 DOM 中不存在版本工具。
- 历史版本不可能被误认为当前内容。
- 360px 宽度下没有横向滚动和四个大按钮挤成两排的情况。
- 长标题、无标签、十个标签、十二个版本和长 Diff 均有明确处理规则。
- 页面完成度以设计验收清单和视觉截图为准，不以“构建成功”为准。
