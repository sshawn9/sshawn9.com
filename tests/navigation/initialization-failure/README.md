# 页面增强初始化失败后的导航收尾

单元测试另覆盖当前导航失败与后续恢复、旧 page-load／loader 失败不得结束新导航、准备和交换阶段异常，以及字体仍未就绪时保留字体等待。单元测试直接驱动本站回调以检查状态归属；浏览器测试负责验证实际 Astro 事件与错误传播。

局部视图导航由 Astro 提交历史，协调器在应用目标视图后继续处理队列，不对调用方暴露完成结果 Promise。设置刷新与导航命令按输入顺序执行，每个操作只解析一次输入并复用同一份 URL 和渲染结果；URL 不变直接刷新，越界通过 Astro replace 提交。等待队列只存尚未执行的操作，执行中的操作独立持有，取消统一清理。测试覆盖 Astro 返回但未提交、取消旧队列、旧交换晚到时不冒充新提交、连续意图、失败后重试、外部导航重新读取偏好、导航取消后仍保留原页面时重新应用已保存偏好，以及历史已提交但视图渲染失败时重新加载当前记录；布局或滚动测量失败只报告错误并继续后续操作，不重载。博客浏览器测试另覆盖实际事件顺序、离开时保留已确认偏好和导航渲染失败恢复。

浏览器用例使用真实本地文章／博客、真实链接与完整 Chromium，覆盖以下场景：

- TOC 注册完自己的监听后，首次标题查询抛错；核对侧栏和 TOC 的真实 AbortSignal 已撤销、没有 article-ready、正文和过渡恢复。预先保存折叠偏好，确认失败页的侧栏仍有真实可见宽度、普通目录链接可点击、偏好没有被清掉；离开后返回重新应用原折叠偏好，展开后控件可正常操作。
- 冷启动失败不发布 `site:runtime-ready`，后续 Projects 链接更换真正的 Document，保留既有整页导航保护。
- `astro:after-swap` 中标题同步失败，确认目标之前确实被置为透明，但最终不残留透明或等待状态。
- loader 准备目标博客文档时抛错，旧正文和 URL 保留、反馈结束，下一次真实导航可用。
- 前进／后退分别在目标准备和交换中失败：地址栏已选中新历史记录，因此必须完整加载该记录，而不是只关进度条、留下旧正文。核对目标正文真实挂载、主文档恰好请求一次、历史长度不变、旧 main 已失效，并可沿反方向回到文章；后退目标含查询及 hash，不能依赖对同一 hash 再赋值就会刷新。

原生加载前同步报告错误；Astro 的拒绝 Promise 若赶在卸载前被浏览器报告，同一错误可能再次出现。测试要求原错必定可见且没有其他错误，不要求宿主只报告一次；不为日志去重增加全局异常抑制。单元测试还覆盖清理本身报错、旧任务晚失败，以及已经交换成功后的局部失败均不误刷新。

注入封装原生查询／监听注册，不添加产品测试接口、不改变字体或动画策略。仅记录文章 resizer 的 pointerdown signal 和文章 click 与 window keydown 共用的 TOC signal，不把其他全局控制器误计为子层资源。每例检查原异常进入浏览器错误通道，不能只靠去掉 ready／pending 标记蒙混。

这些是人为异常边界验证，不代表发现新的自然故障，也不是旧 iPad 模拟。使用默认静态预览，壁纸端点在本地返回 404；不访问生产或第三方 API。不会证明所有 DOM 操作永久失败时仍能恢复，也不替代已有图库、搜索、字体和导航竞态测试。
