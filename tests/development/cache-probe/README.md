# 单机缓存探测

验证资源级探测主流程：连接池、补位调度与按 IP 持续归档能一起正确工作。使用临时本地 HTTP 服务与真实 Undici 请求，不访问生产站；结束后关闭服务并清理本测试创建的数据。

- 默认清单地址指向生产部署；本地文件与 HTTP(S) 清单均可显式指定。下载压缩响应后，归档记录实际解析的 JSON 文本字节数和 SHA-256；HTTP 错误或无效 JSON 不回退到本地清单，带凭据的 URL 不发起请求。
- 真实 CLI 从本地 HTTP 服务下载一次清单，再请求清单中的资源并完成归档；帮助和无效参数不发起网络请求，清单下载期间的 SIGTERM 也能取消并返回 143。
- URL 按完整地址去重，查询参数和未引用资源保留；外站资源不请求，Preview 清单和无效控制参数被拒绝。
- 完整 GET，不附加 Cookie、条件请求或绕缓存参数，不跟随重定向。HTTP 成功不等于缓存 HIT，明确的 404 页面与缺失普通资源分开判断。
- `MISS → HIT → HIT` 后达标；机房变化重新累计连续 HIT，已经达标的资源跳过，其他资源每轮一次、各自最多尝试指定次数。
- 相同出口重跑共用目录和历史，跳过不产生新测量；本次指定新的 N 立即生效，尝试次数每次运行重新计数。不同运行的出口 IP 分目录归档。
- 每次运行只查一次出口 IP，多轮和全部资源跳过时也不增加查询；查询失败时停止，不把资源结果归给未知出口。
- 重跑时先查询 IP，资源请求继续等待该 IP 历史里尚未到期的 429 暂停期限；不扫描其他 IP 的历史。
- 429 响应头先到、正文后到，验证补位立即暂停，遵循 Retry-After 后再等待完整补位间隔；无效或缺失值按 60 秒解析。403 或 challenge 停止后续请求。
- 截断响应不因先收到 HIT 头就判成功。
- 请求开始、429 暂停及资源结果的通知失败会终止本次探测。资源结果通知失败与真实报表写入失败（临时文件位置被目录占用，触发 EISDIR）分别验证：取消仍在下载的响应体，而非等待请求超时；不再补发请求；关闭连接、释放目录锁，保留最初的错误。
- 失败前已经写入的事件日志保留，重新打开归档可恢复有效结果；未完成的下载不能增加 HIT 次数。未模拟磁盘写满或断电，不承诺存储不可写时仍能写出完整结束报表。最终通知再次报错也不能覆盖原始错误。
- 真实 CLI 的 SIGTERM 验证未完成轮次落盘、退出码和带空格的文件路径；每轮 JSON/Markdown 与增量汇总均可读取。

运行：`devenv shell npm exec -- vitest run tests/development/cache-probe/unit.test.ts`。精确计时、传输细节和归档恢复另由相邻的 scheduling、transport、history 案例覆盖。测试不证明 Cloudflare 底层缓存没有误报，也不验证远端部署版本。
