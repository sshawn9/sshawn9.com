# 缓存探测请求调度

验证缓存探测请求只由一只补位计时器渐进启动，不会在单轮开始或并发槽位释放时瞬时填满。测试使用 Vitest 伪时钟和 deferred task，不启动服务、不执行真实传输，也不访问线上网站。

- 首个请求及每次补位都等待独立抽取的完整随机间隔；池未满时，任务结束不会重置已在运行的计时器。
- 达到并发上限时不保留计时器；槽位释放后从释放时刻重新等待，且活动任务数始终不超过上限。
- `pauseUntil` 立即取消补位并保留最晚期限；恢复时重新等待完整间隔。暂停期限跨 `run` 保留，空队列仍可立即结束。
- `stop` 和外部 `AbortSignal` 只阻止新任务，等待活动任务自行收尾；任务失败停止补位、观察其余活动任务的拒绝，排空后拒绝本轮。
- 拒绝重叠的 `run`；超出平台单次 `setTimeout` 上限的等待会拆成安全片段。

运行：`devenv shell npm exec -- vitest run tests/development/cache-probe-scheduling/unit.test.ts`。
