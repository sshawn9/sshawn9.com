# HTML 短时缓存

保障 HTML 在 400 秒新鲜期内可直接复用，手动刷新仍要求验证，不影响哈希资源的一年缓存或数据端点。

使用项目已安装的 Miniflare 原生 Static Assets 处理器读取真实构建产物和 `_headers`，覆盖全部生成页面、首页、独立 404 页面、缺失路径、规范化跳转、Preview 禁止索引，以及未被修改的数据和静态资源规则。浏览器使用真实 HTTP 缓存，验证链接预取后客户端切页不再传输 HTML，而刷新仍产生网络验证；不通过拦截请求模拟缓存。

以 `/` 结尾并匹配 HTML 规则的缺失页面保留 404 状态，也缓存 400 秒，不限语言目录；该地址随后发布为真实页面时，持有旧 404 的用户可能需要刷新。这是已接受的取舍，规则外的缺失页面保持默认缓存策略。

不等待真实的 400 秒到期，期限和过期策略通过响应头核对。Cloudflare 部署后的 `Date`、`Age`、ETag 和控制台规则仍需上线验收。本案例不保证旧 HTML 的资源跨部署永久存在；该发布交界风险已接受，不引入后台更新或资源归档。
