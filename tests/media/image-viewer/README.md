# 文章图片查看器

- 目的：验证显式图片附件先加载响应式缩略图，用户打开时才请求大图；查看器准备/失败时保留原生原图链接，导航取消和卸载不污染后续交互。
- 触发：记录真实图片请求，开图后按 Escape；分别阻断 core、门控 core、首次阻断样式；延迟 About 的真实 fetch，再用当前目录锚点取消；在真实 PhotoSwipe `openingAnimationStart` 回调内点击已有 About 导航链接。
- 预期：点击前没有大图请求；准备中及 core/CSS 失败的点击实际产生原图新标签（核对 popup URL 和图片可见，原文章保留）；准备成功后正常增强；正常关闭后附件焦点、页头宽度和正文滚动位置恢复；取消导航后的第一次开图保持打开；opening 中离页最终移除旧 DOM/全局 viewer，仅销毁一次且不抢新页焦点。
- 自动化覆盖：保留真实缩略图到大图请求、键盘关闭、代表几何、样式失败重试和成功后重取；新增 core 失败/准备门控、取消导航后的首次开图、opening 中卸载。准备门控用 DOMContentLoaded 进入，避免等待完整 load 死锁；取消用真实 fetch 和目录意图，不伪造导航事件。
- 时序证据：opening 用例仅在测试侧观察 `window.pswp` 赋值，再使用库的公开事件和选项；将开场动画设为 3 秒，以核实导航启动和交换均发生在 opening，避免靠 sleep 碰时序。键盘开图覆盖晚到的焦点绑定；断言实际旧 viewer 最终销毁及新页焦点，而非只检查 runtime data 属性。
- 旧实现失败点：core 直到点击才请求且失败后截断原生链接；准备门控要求点击前已请求 core；取消导航残留的关闭标记会在第一次 opening 结束时关闭；opening 期间直接卸载可能留存 viewer 或晚到焦点处理。
- 盲区：未证明完整焦点圈定、逐像素视觉、多图片切换、所有模块组合失败及各浏览器的原图标签呈现；opening 用例扩展真实动画时长，不代表实际用户默认等待时长。
