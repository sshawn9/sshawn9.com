# Plotly 绘图任务结束后的组件清理

使用真实文章、Solid 岛和当前随附 Plotly。测试在库发布 `window.Plotly` 时原位包装同一个 API 对象；不替换绘图库、不延迟模块下载、不向业务增加测试钩子。仅观察文章第一个 `phi` 实验器，以真实 DOM 身份区分离开的实例和返回后的新实例。

六个案例覆盖：主图／副图创建结果尚未交回时离开；真实副图创建后拒绝以模拟部分初始化失败；双图 react 一项拒绝、另一项尚未交回；条件滑块触发的 restyle 在离开后才交回拒绝；尺寸变化触发的第二个 relayout 同步抛错而第一个尚未交回。更新案例还在旧任务未交回时返回文章，确认旧任务不清理新实例，最后正常离开新实例。

门控发生在原 Plotly 调用已经执行并完成之后，仅延迟向组件交回 Promise 结果。日志分别记录 `start`、`native-settled`、`held`、`delivered`／`rejected`；断言真实 `.plot-container` 已创建，再执行站内离开。这证明组件能处理“已发出的任务尚未结算”的生命周期，**不声称真实底层渲染仍在执行，也不测量自然发生概率或垃圾回收后的内存**。同步抛错案例则明确在第二个原生调用前注入异常，验证第一项任务不会因后项同步失败而丢失登记。

每次 purge 都记录所属图、当时未结算数量和连接状态；断言所有未结算任务结束前不能 purge、结束后图形内容与布局对象被回收、每个已开始创建的图只 purge 一次，离开后不再发起绘图或提交旧加载／错误状态，且没有全局错误或未处理的 Promise 拒绝。初始化失败需要在页面仍存在时回收已创建图，并保留错误反馈。

控制使用真实重置按钮、条件滑块键盘操作、窗口调宽和站内导航；不重复现有图形数学、截图、标签布局和完整键鼠交互测试。不访问线上壁纸 API：沿用 Playwright 默认静态预览，其本地名单端点返回 404。
