# 图形聚焦恢复与下一次操作的顺序

使用真实 `planar-frenet-frame` 静态图，保留全局 `scroll-behavior: smooth`，不加载 Plotly。前三例真实点击关闭按钮，在应用已完成关闭的同一次 click 冒泡末尾安排后续动作：点击现有目录并聚焦该链接；显式滚到页首并聚焦另一现有控件；立即再次点击原按钮重开。后续动作属于**受控同任务时序**，不代表已测量人工快速操作的发生概率。

RAF 仅用于逐帧观察，不拦截或改写任何回调，也不禁用动画。验证后续八帧的位置、焦点、图形 DOM 身份及弹窗状态；目录用例还等待平滑滚动到实际标题，再检查八帧稳定状态。重开用例等待真实原生 `close` 事件确实到达，防止只验证重开瞬间而漏掉旧事件误关新弹窗。

第四例门控本地 About 的真实导航响应，聚焦期间调用现有 About 链接发起导航（明确是程序调用，因 modal 会阻止直接点击背景控件），再以真实目录点击取消。验证原图归位、无残留占位、仍能再次打开关闭，不改写导航协议或业务处理器。只暂缓请求完成，不伪造页面导航事件；finally 释放门控。

每例使用独立浏览器上下文及现有完整 Chromium 配置。静态预览壁纸 API 本地返回 404，不访问线上接口。正常开关、窄屏长图及 Plotly 相机保留由原有相邻测试覆盖；这里不重复其布局或数学断言。
