# 每页篇数单选控件

收起时，中文显示“每页 5 篇”、英文显示“5 per page”，使用各自完整的本地化模板；展开选项在两种语言中均只显示数字：详细模式为 5、10、20、50，紧凑模式为 15、50、100。整句构成一个 combobox，读屏名称分别为“每页篇数”和“Articles per page”。阅读偏好拥有已确认的数量，页面视图呈现数量与勾选标记，控件仅管理开合和临时定位；确认才保存偏好并触发视图刷新，Esc、Tab、点击外部或再次点击触发区域均取消临时定位。输入数字可定位预设。

按钮按当前语言最长的篇数文案固定宽度，切换篇数或详细／紧凑模式均不伸缩。CSS 在首屏按全部预设的最大值预留宽度，当前文案右对齐，文字与箭头始终间隔 0.375rem；不依赖运行时测量，也不为另一种语言额外留白。菜单通过现有 Floating UI 尺寸处理与按钮等宽，保留视口边界限制；触屏按钮和选项仍至少高 44px。

弹层采用站点绘制的实色表面，文字颜色与背景成对定义。选中勾、定位行背景与键盘焦点各自独立。浏览器用例实际打开菜单，检查两种主题下所有选项及定位行的文字对比度、触屏行高和键盘操作。键盘焦点通过 Tab 导航进入，避免把不同浏览器对“鼠标聚焦后按键”的启发式差异当成控件错误。

Floating UI 负责跟随、翻转、边界限制和内部可用高度。普通滚动跟随触发区域；触发区域离开视口、窗口或缩放改变尺寸、离开页面时关闭。覆盖快速重新打开、取消原生打开、短视口的内部滚动、窗口调整后重新打开和旧菜单随页面释放。测试注入 CSS zoom 仅验证尺寸变化时取消展开，不把它等同于浏览器缩放；站点本身不使用 CSS zoom，浏览器菜单缩放仍需人工验收。

刷新时，首屏显示已保存的篇数，控件在交互初始化期间保持原生禁用，但不降低透明度。桌面和手机回归会实际保存 10 篇、刷新并延迟运行时加载，截图时隔离手机标签折叠导致位置变化的页面底纹，逐像素比较启用前后的文字和图标，同时检查值不变、没有额外文档加载，启用后仍可修改篇数。

可用时采用原生 Popover 顶层；不支持该 API 时，使用同一套 DOM、键盘和提交规则的固定定位回退。页面初始化失败时按钮保持禁用，菜单回到原页面；原有文章与分页链接仍可使用。

这些自动化用例验证交互、几何关系、颜色和可访问语义，不代替读屏器真人操作及实际 Safari／iOS 设备验收。
