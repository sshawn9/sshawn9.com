# 换图失败或取消后可以重试

预置当前照片但不预置下一槽，先让候选图片请求失败，检查当前照片与署名保持不变，Next 的忙碌状态结束；恢复图片响应后再次点击必须能成功换图。

关闭 scenic 会永久取消尚未提交的这次 Next；重新打开不恢复旧意图，后台备图仍独立进行，已经提交的当前照片不回滚。

- 解码重叠：预置当前 A / 备用 B，门控前两次真实 data URL decode。旧 Next 等待时 off/on，在旧 gate 未放行时再次 Next；旧 decode 随后完成不得消费 B 或清掉新操作的 busy，新 decode 放行后才提交 B。
- 等待备图：不预置备用槽，门控后台 B 图片请求。Next 等待备图时 off/on，后台请求继续且只完成一次；补图后连续帧仍显示 A、B 留在备用槽，显式新 Next 才提交 B。这覆盖第一次 await 之前就必须确定操作身份的边界。
- 提交后取消：在真实淡入动画 ready 后暂停并推进到中途，确认 B 已提交，再 off/on；B 不回滚，也不会在淡入完成前挂轮播计时。结束真实动画后只启动一个新的 5–9 分钟计时。

关闭景观时照片本就不可见，因此不要求该阶段照片仍可见。所有远程图片和清单均使用固定夹具，不访问线上 API；解码调用仍执行原生 decode，只门控 Promise 完成。时序用请求、真实 transition 事件和逐帧观察，不用 sleep 猜竞态。

旧代码会在旧解码未结束时继续锁住 Next，并可能在重新开启后恢复旧提交；只在 decode 之后检查版本也漏掉等待备图的取消。提交后用例是行为保护，不要求旧代码必须失败。

单元测试另外检查取消立即结束解码等待、清除定时器和 abort 监听、释放图片引用，以及原有 10 秒超时仍有效。取消本站等待不等于保证浏览器立刻终止底层解码。

盲区：不模拟所有图片编码器错误；逐帧观察不是无限期保证；真实暂停动画仍受生产 watchdog 约束。完整 5–9 分钟轮播机制与补图独立性另由 rotation-reset 等用例覆盖。
