# 壁纸图层接管与覆盖式淡入

显示图层不再绑定 a/b 存储槽。HTML 只提供一个初始图层，head 中的同步 CSS 图片维持首屏；完整视觉节点及署名解析后才接管。下一张完成准备和解码后在上层淡入，下层不主动变透明；某层完全显示后只删除其下方被遮住的图层，停止切换后最终只剩一层。

单测使用真实 View 与可控动画，检查分段 DOM、未就绪不假报成功、较旧／较新图层先完成、迟到回调、跨页重新连接同一视觉节点、启动和结束兜底。兜底必须显示已解码的目标并清理资源，不只是停止按钮转圈；被覆盖／销毁与最终显示采用不同完成结果。

浏览器回归插入真实解析脚本检查点，复现内部图层尚未出现时的 MutationObserver 回调；另核对下层始终不透明、上层真实淡入、站内导航两种节点搬移方式均保留相同图层和动画对象，以及淡入中启用减少动态效果立即收尾。使用不同的 1600×900 JPEG 连续切换 12 次，检查图层回收到一层并记录帧间隔；该记录不代表 GPU 内存或旧设备性能结论。解码失败／取消、轮换期限、缓存刷新及署名仍由现有壁纸案例覆盖。

只使用本地预览和固定图片，不请求真实壁纸 API。动画的主观观感与旧 iPad 上的绘制性能仍需实机复核。
