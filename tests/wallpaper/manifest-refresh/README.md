# 照片名单按自己的期限刷新

照片名单的真实请求结束后安排下一次检查：有可用名单时 5 小时，没有名单时失败后 30 秒重试。内存读取、换图、后台补图、主题和景观开关不得把期限往后推。并发加载共享同一个请求；失败保留已有名单。

无名单的失败退避期间，`online`、主题切换等普通 reload 也遵守这 30 秒期限，不立即重复请求。

页面隐藏只撤下定时器，不抹掉名单期限。恢复可见时，未到期就继续等待剩余时间；已经过期就补查一次，不追赶每个错过的周期。这与自动换图的 5–9 分钟计时是两件事。

单元测试使用可控时间验证请求、缓存与失败期限；浏览器测试推进时钟并统计真实发出的、由固定路由响应的名单请求，覆盖换图和补图后的原定时刻、后续周期以及隐藏恢复。不访问线上 API 或 Unsplash，也不实际等待数小时。

名单单次请求的 60 秒上限覆盖等待响应头和读取 JSON 响应体，不只是用 Promise 超时提前返回。单元测试向请求传入真实 AbortSignal：模拟响应头一直不返回，或响应头已到但 ReadableStream 响应体挂起，均断言期限触发 abort、合并的调用结束、pending 释放，以及无名单时仍等待 30 秒再重试。

已有名单的刷新超时保留旧名单，请求结束后仍采用 5 小时间隔。超时后的新请求使用独立信号并可成功；成功、非 2xx、内容类型错误及 JSON 解析失败均清除请求计时器。非 2xx 和内容类型错误会立即 abort，避免未读响应体继续传输；成功和解析失败不会被迟到计时器误 abort。

边界：单元测试的受控 fetch 在收到 abort 时拒绝，响应体流也据此报错；它验证信号与状态清理，不声称证明操作系统连接已关闭。真实 HTTP 挂起和主动原图下载的 120 秒取消由其他测试验证，本目录单元测试不访问线上服务。
