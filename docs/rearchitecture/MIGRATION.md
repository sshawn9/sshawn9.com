# 全站重构迁移与回滚计划

- 状态：执行中；当前进行 M4R.6.7 集中验收与复杂度审计
- 前提：ADR-001、ADR-002 与现行行为契约
- 原则：工作树、默认命令和部署流程只保留当前运行时

阶段 0 至 4 已完成，当前先关闭 M4R 基座收口，再进入阶段 5。旧根应用、旧测试、旧配置和旧专属依赖已按 2026-09-03 的决定提前删除；这不等于提前通过平台验收或切换生产流量。

## 为什么采用并行应用

当前路由、外壳、字体和滚动通过多套全局生命周期耦合。直接在生产入口上逐个替换会长期存在两个路由器、两套状态恢复或两种事件语义，难以判断故障属于哪一代。

正式重构在独立应用目录和 Preview 中进行，复用内容事实和纯领域逻辑。当前源码收敛为单一应用；生产切换仍须通过平台门槛，旧生产版本继续作为 Cloudflare 可回滚版本保留。

## 阶段

### 0. 契约和设计

- 完成行为治理、证据基线、ADR 和双 POC；
- 不修改线上行为；
- 处理所有待讨论的行为提案。

### 1. 垂直切片

- 在隔离实验目录实现 Astro 与 Qwik 候选；
- 使用同一 fixture、测试和 Cloudflare Preview 条件；
- 选出一个通过全部硬门槛的方案，删除失败候选的运行时代码。

### 2. 新应用骨架

- 创建独立 v2 应用和构建输出；
- 建立纯领域层、内容适配层、基础 layout、SiteShell、StateLedger 和 RequiredFonts；
- 先实现首页、About 和普通文章的完整静态 HTML；
- 部署到独立预览 Worker/alias，不绑定生产域名。

### 3. 导航和主要内容路径

- 博客列表、标签、分页、左右 Sidebar、目录和历史恢复；
- 语言切换；项目页面完成后再一次接入完整搜索；
- 冷/温缓存、慢网络、字体失败和快速导航连续帧；
- 现有视觉参数保持不变，差异必须形成行为提案。

### 4. 研究交互迁移

- 先迁移服务端正文、静态回退和最终几何；
- 再逐个接入现有 Solid 岛或重写后的默认 UI 岛；
- 每个图形单独通过模型、交互、主题、语言、聚焦和销毁测试；
- 不进行全文章一次性客户端化。

### 5. 平台和发布

- Pagefind/搜索代际、sitemap、robots、草稿和 Preview；
- Static Assets 直出、缓存、Access、不可变版本和回滚演练；
- 使用已经验证的同一构建产物部署，不在部署步骤重新构建。

### 6. 生产切换

- 旧源码、旧测试、旧配置、旧专属依赖和临时兼容分支已提前删除；
- 仓库默认 check、build、preview、CI 与 Wrangler 已收敛到当前应用；
- 在不可变版本 URL 完整验收当前应用；
- 将生产流量一次性切到已验证版本；
- 保留最后一个已验证的旧 Cloudflare 版本作为立即回滚目标；
- 观察期结束后关闭旧平台版本的回滚资格。

## 生产切换硬门槛

- 所有现行行为案例都有通过证据或明确、已批准的替代契约；
- 代表路径连续帧不存在禁止状态；
- 字体失败保持已批准的加载边界；岛屿失败和存储失败不得损坏已提交内容；
- 同构建持久外壳、快速取消、前进后退和多滚动区恢复通过；
- 所有用户可见差异均有已批准提案；
- 静态页面不产生 Worker 调用；
- Preview、Production、Access、缓存、版本地址和回滚演练通过；
- CI 构建、测试和部署消费同一份已验证产物；
- 新架构没有旧 Swup 事件、全局 runtime registry 或跨框架共享可变 store；
- 依赖、bundle、长任务和主要文件复杂度报告已审查。

## 回滚

### 切换前

当前应用只存在于独立 Preview；失败时停止其部署，不影响仍在运行的生产版本。源码问题通过 Git 历史定位，不在工作树恢复第二套应用。

### 切换后

1. 将 Cloudflare 流量恢复到最后一个已验证的平台版本；
2. 不现场从历史源码重新构建回滚版本；
3. 验证规范域名、API、静态资产和搜索均回到同一构建代际；
4. 保存失败版本的不可变地址、trace 和构建产物用于分析；
5. 修复后产生新版本，重新走完整切换门槛。

内容 schema 的破坏性迁移必须在切换前提供双读或可逆转换，否则不能依赖平台回滚恢复旧应用。

## 防止迁移形成第二套系统

- 不保留双写、双 store、双路由器、兼容事件或历史存储迁移分支；
- 历史代码只能通过 Git 历史查阅，不回流为兼容层；
- 领域逻辑以当前需求和稳定接口为单位，不复制后再各自修补；
- 测试跟随需求和行为契约；不得为了历史测试保留当前不需要的代码；
- 每次改动按一个行为领域闭合代码、必要文档、测试和删除项；
- 任何无法说明状态所有者的模块不得进入下一阶段。
