# 全站重构迁移与回滚计划

- 状态：执行中；M4R.6.1 至 M4R.6.6 已完成，当前进行 M4R.6.7 集中验收与复杂度审计
- 前提：ADR-001、ADR-002、BCP-001、BCP-002、BCP-003 与 BCP-004 已接受
- 原则：新旧运行时不在同一个生产页面中并行接管导航

阶段 0 至 4 已完成，当前先关闭 M4R 基座收口，再进入阶段 5；阶段 6 完成前旧应用仍是生产构建和即时回滚来源，不能提前删除。

## 为什么采用并行应用

当前路由、外壳、字体和滚动通过多套全局生命周期耦合。直接在生产入口上逐个替换会长期存在两个路由器、两套状态恢复或两种事件语义，难以判断故障属于哪一代。

正式重构应在独立应用目录和独立 Preview 中进行，复用内容事实和纯领域逻辑，不复用旧页面运行时。通过全部切换门槛后一次性替换生产应用，旧生产版本继续作为 Cloudflare 可回滚版本保留。

## 阶段

### 0. 契约和设计

- 完成行为治理、证据基线、ADR 和双 POC；
- 不修改线上行为；
- 处理所有待讨论的行为提案。

### 1. 垂直切片

- 在隔离实验目录实现 Astro 与 Qwik 候选；
- 使用同一 fixture、测试和 Cloudflare Preview 条件；
- 选出一个通过全部硬门槛的方案，删除失败候选的运行时代码。

### 2. 新应用骨架

- 创建独立 v2 应用和构建输出；
- 建立纯领域层、内容适配层、基础 layout、SiteShell、StateLedger 和 RequiredFonts；
- 先实现首页、About 和普通文章的完整静态 HTML；
- 部署到独立预览 Worker/alias，不绑定生产域名。

### 3. 导航和主要内容路径

- 博客列表、标签、分页、左右 Sidebar、目录和历史恢复；
- 语言切换；项目页面完成后再一次接入完整搜索；
- 冷/温缓存、慢网络、字体失败和快速导航连续帧；
- 现有视觉参数保持不变，差异必须形成行为提案。

### 4. 研究交互迁移

- 先迁移服务端正文、静态回退和最终几何；
- 再逐个接入现有 Solid 岛或重写后的默认 UI 岛；
- 每个图形单独通过模型、交互、主题、语言、聚焦和销毁测试；
- 不进行全文章一次性客户端化。

### 5. 平台和发布

- Pagefind/搜索代际、sitemap、robots、草稿和 Preview；
- Static Assets 直出、缓存、Access、不可变版本和回滚演练；
- 使用已经验证的同一构建产物部署，不在部署步骤重新构建。

### 6. 生产切换

- 冻结旧应用功能开发，只接受生产故障修复；
- 在不可变版本 URL 完整验收 v2；
- 将生产流量一次性切到 v2 版本；
- 保留最后一个旧应用版本作为立即回滚目标；
- 观察期结束后删除旧源代码、旧测试、旧配置、旧专属依赖和临时迁移适配器；
- 将仓库默认 check、build、preview、CI 与 Wrangler 产物路径全部收敛到 v2，不保留两个可部署入口。

## 生产切换硬门槛

- 190 个行为案例全部有通过证据或明确、已批准的替代契约；
- 代表路径连续帧不存在禁止状态；
- 字体失败保持已批准的加载边界；岛屿失败和存储失败不得损坏已提交内容；
- 同构建持久外壳、快速取消、前进后退和多滚动区恢复通过；
- 所有用户可见差异均有已批准提案；
- 静态页面不产生 Worker 调用；
- Preview、Production、Access、缓存、版本地址和回滚演练通过；
- CI 构建、测试和部署消费同一份已验证 v2 产物，生产流程不再隐式构建根目录旧应用；
- 新架构没有旧 Swup 事件、全局 runtime registry 或跨框架共享可变 store；
- 依赖、bundle、长任务和主要文件复杂度报告已审查。

## 回滚

### 切换前

v2 只存在于独立 Preview，失败时删除或停止部署 v2，不影响生产。

### 切换后

1. 将 Cloudflare 流量恢复到最后一个已验证旧版本；
2. 不现场重新构建旧代码；
3. 验证规范域名、API、静态资产和搜索均回到同一旧代际；
4. 保存失败 v2 的不可变版本、trace 和构建产物用于分析；
5. 修复后产生新 v2 版本，重新走完整切换门槛。

内容 schema 的破坏性迁移必须在切换前提供双读或可逆转换，否则不能依赖平台回滚恢复旧应用。

## 防止迁移形成第二座屎山

- 不以“迁移期”为理由永久保留双写、双 store、双路由器或兼容事件；
- 每个临时适配器记录删除阶段和唯一调用方；
- v2 不导入 `src/scripts/page-router.ts`、`client-runtime.ts` 或旧全局 store；
- 领域逻辑迁移以测试和接口为单位，不复制后再各自修补；
- 迁移 PR 按一个行为领域闭合代码、文档、测试和删除项；
- 任何无法说明状态所有者的模块不得进入下一阶段。
