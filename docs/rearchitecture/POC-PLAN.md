# 双垂直切片验证计划

- 状态：已完成并冻结；Qwik 已触发正文重复交付硬门槛，Astro 被选为正式 v2 基础；结果见 [`../../experiments/rearchitecture/RESULTS.md`](../../experiments/rearchitecture/RESULTS.md)
- 用户可见影响：无；两个切片只部署到隔离预览地址
- 候选 A：Astro SSG + ClientRouter + 静态 Astro SiteShell + 独立交互岛
- 候选 B：Qwik City SSG + Qwik Router

## 目的

验证两套架构能否在真实最差路径中同时满足静态 HTML、持久外壳、连续帧稳定、复杂状态恢复和免费静态部署。POC 不是框架教程，也不以“能跳转页面”为完成标准。

任一硬门槛失败即淘汰；评分只用于比较都通过硬门槛的候选。

POC 已完成技术选型，不再承载正式产品开发。剩余的真实内容、跨浏览器和 Cloudflare 平台验证随正式 v2 在对应主线阶段完成。

## 代表路径

两个切片使用同一内容、样式 token、字体、背景和测试脚本：

1. 直接打开中文博客列表；
2. 选中 `Frenet` 标签并调整、滚动左侧 Sidebar；
3. 进入最长的 Frenet 研究文章；
4. 滚动正文和右侧目录，启动一个轻型交互图和一个重型图形占位；
5. 调整右侧 Sidebar，切换主题和语言；
6. 浏览器后退，恢复标签、分页、主滚动和 Sidebar 滚动；
7. 快速执行列表 → 文章 A → 文章 B，制造迟到请求；
8. 用不同构建 ID 重复一次导航，验证 `BCP-001` 假设，但不改变生产行为。

内容 fixture 必须接近真实最长文章的 HTML 体积和标题层级，但不得把正文作为 JavaScript 对象导入，否则会人为偏袒某个候选。重型运行时仅在对应岛实际进入加载条件后请求。

## 固定环境

| 维度       | 条件                                                    |
| ---------- | ------------------------------------------------------- |
| 视口       | 1440×900、390×844、820×1180                             |
| 缓存       | 空缓存首次访问、温缓存刷新、温缓存站内导航              |
| 网络       | 正常本地；固定 RTT/带宽限制；字体额外延迟；单个字体失败 |
| CPU        | 正常；固定 CPU throttle                                 |
| 输入       | 指针、键盘、触摸模拟、浏览器前进后退                    |
| 动画       | 默认；`prefers-reduced-motion: reduce`                  |
| 构建       | 同一构建；A 页面来自构建 1、目标页面来自构建 2          |
| JavaScript | 正常、延迟、禁用、交互岛 chunk 失败                     |

所有延迟由统一测试代理或浏览器路由规则注入，不能在候选代码中增加测试专用 sleep。

## 硬门槛

### 静态文档

- 禁用 JavaScript 后，两个页面都有完整导航、列表、标签链接、文章、目录、图注和静态图形说明；
- HTML 中不存在必须等客户端 payload 才能生成的正文；
- 文章正文不能以同阶体积再次序列化进 JavaScript 或 JSON payload。

### 连续帧与字体

- 冷缓存、字体延迟和字体失败时均不得出现无样式旧页、错误列表、双份正文或布局塌缩；
- 等待目标字体和样式时，旧页面保持完整且持久控件仍可操作；
- 目标页面只提交一次；接管不得再做可见几何修正；
- 热缓存导航不得出现字体替换或重播 reveal。

### 导航与生命周期

- 同构建导航时 SiteShell 关键 DOM 节点引用保持不变；
- 只有页面出口替换，Header 和壁纸 DOM 保持持久，文档级控制器不重复安装；
- 快速导航中只有最后事务可以提交，旧 island 不得在离场后复活；
- 键盘导航焦点、路由播报和无脚本链接保持有效；
- 目标页面样式准备失败时具有确定降级，不暴露半提交文档。

### 状态与历史

- URL 状态、主滚动、左右 Sidebar 滚动和目录滚动按历史项恢复；
- 同一路径的两个历史项可以恢复不同位置；
- 水合/恢复噪声不能覆盖真实用户在等待期产生的新滚动；
- 主题、壁纸和 Sidebar 偏好刷新首帧直接正确；
- 存储不可用或数据损坏时仍有安全默认行为。

### 交互岛

- Sidebar 几何变化不重建研究图；
- 重型依赖在需要前不请求；
- chunk 失败保留 SSR 回退；
- 岛屿状态、监听器和对象在离场时有可观测的单次释放。

### 部署

- 构建输出可以直接由 Cloudflare Static Assets 部署；
- HTML、CSS、JS、字体和图片请求不调用 Worker；
- Worker 只处理测试 API 路径；
- 构建 1/2 的资产引用和搜索 fixture 不混合。

## 测量指标

记录数据而不是提前猜测绝对预算：

- HTML、CSS、共享 JS、页面 JS 和重型 island 的原始/Brotli 体积；
- 首次文档请求数、导航请求数、重复请求和 Worker 调用数；
- 首帧、可交互、导航准备、swap 和 settling 时间；
- CLS、长任务、主线程脚本执行和水合/恢复耗时；
- 冷/温缓存下字体请求及目标正文首次出现时间；
- 同一用例的连续帧截图、DOM 几何采样和 Chrome trace；
- 生产模块数量、公共接口、最大文件行数和框架耦合点。

不设置一个可以用牺牲行为换取的综合性能分数。行为硬门槛始终高于体积和时间排名。

## POC 代码规则

- 两个候选位于独立实验目录，拥有独立依赖和构建输出，不修改生产入口；
- 共享 fixture、测试驱动、设计 token 和字体，不共享候选的运行时代码；
- 不复制现有 Swup controller、全局事件或 nanostore 状态作为捷径；
- 核心状态转换先写纯 TypeScript 测试，再连接框架适配器；
- 每个模块必须有一句职责说明和明确公共接口；
- 单文件一旦承担两个独立生命周期，就在 POC 阶段拆分；
- 临时探针放在测试适配器中，不能进入生产 bundle；
- POC 结束后只迁移通过审查的设计，不整目录复制实验代码。
