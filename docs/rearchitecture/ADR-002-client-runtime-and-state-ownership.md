# ADR-002：客户端运行时与状态所有权

- 状态：2026-09-30 字体失败重试已通过本地验证；Firefox 连续真实 F5 的画面连续性仍未通过，Safari 尚未实测
- 日期：2026-08-28
- 接受日期：2026-08-29
- 决策范围：导航、状态恢复、绘制前状态、字体、滚动和组件生命周期

本记录说明当前运行时边界，不冻结历史交互参数。具体行为以当前确认的需求为准，测试案例记录验证依据；改变行为时需明确说明取舍。

## 核心规则

1. ClientRouter 拥有文档导航与历史遍历；本站通过公开生命周期接入文档准备和同页视图更新，不另建路由器、head 管理器或历史索引。
2. 每类状态有明确的权威来源；内存、DOM 投影和持久化快照各司其职，不互相争夺所有权。
3. 客户端运行时按职责拆成小型 TypeScript 模块；可复用逻辑使用显式类型化参数，不使用全局注册表或字符串事件总线。
4. 页面控制器由 PageRuntime 挂载和销毁；交互岛、自定义元素拥有自身生命周期。
5. 首帧恢复代码通过构建期入口直接导入运行时的类型、schema 和纯函数，不复制实现或序列化函数源码。

## 组合根

`BaseLayout` 是文档生命周期的组合边界；静态 SiteShell 本身不水合：

```text
BaseLayout（Astro 静态文档）
  ├── InitialDocument（独立脚本，必需样式与字体成功后提交内容）
  ├── WallpaperSystem（head 启动并独立持续运行）
  ├── SiteShell.astro（目标文档权威 Header）
  ├── BackdropSurface 内壁纸视觉层（跨页保留）
  ├── NavigationProgress（反映准备状态，跨页保留进度动画）
  ├── SiteRuntime（唯一的正常浏览器运行时组合根）
  │   ├── NavigationCoordinator（代际、进度、字体门槛、转场和焦点）
  │   ├── PageRuntime（页面准备与当前页面挂载/销毁）
  │   ├── TransientOverlayController（短暂浮层）
  │   └── Content UI custom-element definitions
  └── 页面交互岛（各自拥有 mount/unmount）
```

目标文档是 Header 文案、链接、当前项和可访问语义的唯一权威来源。独立 WallpaperSystem 从 head 的同一个入口运行，在交换前投影主题、壁纸、署名和控件状态；跨页保留纯壁纸视觉层和无页面文案的进度线，不保留旧 Header 并手工复制目标属性。其余长期控制器只由 SiteRuntime 安装，组合根持有每个销毁函数。

PageRuntime 是博客、文章和搜索页面的准备、挂载与销毁所有者；它向 NavigationCoordinator 提供目标文档准备能力和当前页面的局部视图接口。文档交换前销毁旧页面，`page-load` 挂载当前页面；同一 `main` 不重复挂载，局部视图更新不销毁页面。普通文档离开时 SiteRuntime 释放资源；进入浏览器 back-forward cache 时保留实例供恢复。

运行时通过显式接口连接控制器，优先使用 Astro 的公开生命周期和明确 DOM 语义。必要的框架适配集中处理并记录版本耦合，不依赖生产调试全局对象或按字符串查找控制器。Solid 岛由框架拥有 mount/unmount。

静态外壳避免在首屏关键结构之前执行框架 island bootstrap。普通 TypeScript 只增强已有可访问 HTML；Solid 仅在独立交互岛中使用。初始文档与导航复用字体需求判定和页面状态准备；首次内容在必需样式与字体成功后挂载，站内导航在旧页仍显示时异步准备目标字体。

## 导航事务

实现入口为 [NavigationCoordinator](../../apps/site/src/runtime/navigation-coordinator.ts)，页面只通过 [PageView / PageNavigation](../../apps/site/src/runtime/page-navigation.ts) 声明局部变化。三类操作的边界不同：

| 操作                             | URL／历史                   | 页面处理                                    |
| -------------------------------- | --------------------------- | ------------------------------------------- |
| 跨文档导航                       | ClientRouter 提交历史       | 获取目标 HTML，准备后交换文档               |
| 当前博客筛选、分页及同页历史遍历 | ClientRouter 提交或遍历历史 | 保留文档，历史提交后应用局部视图            |
| 搜索输入、初始 URL 规范化        | 协调器替换当前历史项        | 不产生新页面访问，不触发 Astro 导航生命周期 |

### 文档导航

本站在 Astro 的公开生命周期中接入以下步骤，事件接口见 [官方文档](https://docs.astro.build/en/guides/view-transitions/#lifecycle-events)：

```text
before-preparation：保存当前状态，启动导航反馈
  └── 原始 loader：获取、解析目标 HTML 和准备样式
      └── 构建代际检查 → 展开目标模板 → 页面状态准备 → 必需样式与字体 → 离场动画
after-preparation
before-swap：投影当前外观状态，销毁旧页面，由框架交换文档
after-swap：恢复所需滚动与焦点，进入目标页面
page-load：挂载当前页面，结束对应导航反馈
```

目标文档判断必须在原始 `loader()` 成功完成后进行；事件刚创建时的 `newDocument` 不能当成已获取的目标。获取失败、不支持客户端导航或构建代际不匹配时走完整文档导航，不把新 HTML 交给旧运行时。客户端导航展开待提交模板，在当前文档中准备目标所需的样式与字体，完成前不交换文档。

准备期间保留旧页面及仍可用控件；事务被替代后，旧结果不能提交。导航取消信号由 ClientRouter 提供，本站不另建导航 AbortController；页面功能仍可用自己的 AbortController 取消搜索任务或释放监听。

导航反馈区分真实等待与进度条呈现。开始准备立即发布 `data-navigation-pending`；新一段等待设置 120ms 的显示计时器。资源准备完成的处理先执行，就取消该计时器；计时器回调先执行，就进入 `active` 并启用进度动画。后续离场动画或提交收尾不会单独触发进度显示，整次切页总耗时不是判断条件。已启动的 `active` 阶段至少保持 240ms，不代表条段连续位于屏内 240ms；正常完成后按原样式退出右侧并淡出 120ms。这些视觉计时不延迟正文提交或 `aria-busy` 清理。

`NavigationProgress` 根据初始文档的 `data-font-state="loading"` 或导航的视觉阶段启用动画；`main` 的 `aria-busy` 只取决于真实字体/导航等待，不跟随视觉收尾。这些状态不再通过全局 CSS 隐藏 Header 或正文。首次正文及就绪标记在资源成功后同时提交，进度线是否绘出不能代替刷新时内容连续可见的验收。

连续导航接管尚未触发的显示期限或已经启动的进度动画，不重置等待；旧事务的完成或取消不能清除新事务。Astro 在同一轮调用中先中止旧导航再发出替代准备事件，因此协调器在一个微任务中清理匹配的旧反馈：有替代者则由新 revision 接管，否则在下次绘制前清理。无继任导航的取消和销毁立即清除，不走成功淡出。进度线位于 Header 内，与 Header 一起定位和滚动，不另设浮层、不拦截交互。视觉按旧版保留：单条段、2px 高、26% 宽、原有颜色，以条段自身宽度为基准从 `-110%` 移至 `390%`，周期 1.1s，使用 `cubic-bezier(0.45, 0, 0.55, 1)`；包含起步和循环交界的离屏空窗，不做左右接续或往返。正常完成时移至右侧屏外并淡出，不停在原处淡出。减少动态效果沿用全局缩短动画至一次的规则，不新增静态条段。

### 局部视图更新

- 页面声明当前文档能表达的 URL 参数范围；路径、语言或其他资源身份不同则走文档导航，协调器不包含博客或搜索专属判断。
- 对可复用文档的导航，通过公开 `loader`／`swap` 接口跳过获取与文档替换，让 ClientRouter 正常提交历史；随后同步应用局部视图及滚动，不播放整页转场、不重新挂载 Header、Sidebar 或研究岛。
- 连续操作基于最近请求的 URL 组合；新的文档导航可以终止未完成的局部操作，迟到结果不能再把用户带回旧视图。
- 保留整个文档时，Astro 的 route announcer 不会随旧 body 消失。协调器集中清理旧 `.astro-route-announcer`，局部更新抑制页面级播报，文档导航恢复播报。这是明确的版本耦合点，升级 Astro 时复核对应测试。

### 构建代际

共享 Astro 配置初始化时生成一次 UUID，注入 HTML meta、客户端代码与 Pagefind `meta-cache-tag`。构建标识不读取外部环境变量，也不关联版本号；新构建使用新标识，同一次开发配置初始化内共用标识。消费或部署产物时不改写标识。

测试从实际产物读取并核对标识，拒绝缺失、非法或固定的开发占位值；检查同代导航、跨代完整文档导航及真实搜索请求。缓存规则和部署验证边界见 [缓存说明](../cloudflare-browser-cache.md)。

### 状态所有权表

| 状态                                          | 权威来源                             | 原因                                                       |
| --------------------------------------------- | ------------------------------------ | ---------------------------------------------------------- |
| locale、route、tag、page、query、version      | URL                                  | 可分享、可刷新、可由服务端独立重建                         |
| 普通前往目标页或锚点的主滚动                  | Astro ClientRouter                   | 保留框架默认导航语义                                       |
| 刷新、历史遍历和嵌套滚动恢复                  | `history.state.sshawn9` 中的本站快照 | 有有效快照时统一恢复主滚动与嵌套区；缺失时保留框架默认行为 |
| 主题、壁纸开关、语言偏好、Sidebar 几何        | `localStorage`                       | 跨标签页会话或跨会话的用户偏好                             |
| 当前/下一张壁纸、随机队列、一次性导航状态转移 | `sessionStorage`                     | 固定双槽位，只在当前标签页存活                             |
| 导航进度、打开的全局浮层                      | 对应文档级控制器内存与语义 DOM       | 瞬时 UI，不应写入存储                                      |
| 页面内交互参数                                | 交互岛本地状态                       | 当前不提供通用持久化 channel                               |
| 文章、语言、版本、标签和项目关系              | 构建期领域模型                       | 内容事实，不由浏览器推断                                   |
| 构建代际                                      | HTML meta + 构建常量                 | 检测目标文档与当前运行时是否匹配                           |

### History schema

本站快照的 schema 与合并规则由 [state-ledger.ts](../../apps/site/src/runtime/state-ledger.ts) 定义，文档不再复制另一份类型声明。

- 写入使用 `{ ...history.state, sshawn9: nextSiteState }`，禁止覆盖整个 `history.state`；
- 读取必须 schema 校验、数值钳位并安全忽略未知版本；
- 嵌套滚动按历史项保存，不能只按 pathname 保存；
- 存储失败时退化为默认状态，不能阻塞核心导航。

历史遍历时，有效本站快照在框架交换后同时恢复主滚动与嵌套滚动，避免被替代导航提前改写框架滚动缓存。语言切换另用一次性位置转移；普通前往新页面或锚点仍保留框架语义。

### 语言与搜索边界

- 带语言前缀的 URL 是当前界面语言的权威来源；中立 `/` 只按“已保存偏好 → 浏览器语言 → 英语”选择入口，不建立服务端语言会话。
- 语言切换保持同一逻辑内容身份、query 和 hash；回退正文只在内容根标明实际语言，不能反向改变界面语言。
- 搜索查询以 URL 为权威来源，HTML 与 Pagefind 索引属于同一构建代际。
- Pagefind 负责索引、检索、输入组件，以及翻译和播报接口；本站 search controller 负责查询任务、URL、组合输入、取消、批次加载和失败恢复，results view 负责结果 DOM、结果区键盘与焦点。
- 新结果和所需字体在提交前准备，摘要与卡片一次替换；等待期间保留上一组已提交结果，失败不把新查询描述误配给旧结果。不要求不同查询间共同命中的卡片保留节点身份。

### 主题与景观背景边界

- 主题与景观开关使用共享偏好；当前照片、下一张照片和队列使用每标签页固定双槽位；可见 DOM 只是状态投影。
- 双槽位只属于存储，不再对应 DOM 的 a/b 图层。首屏以单一初始图层读取 head 投影的 CSS 图片；视觉容器、初始图层和署名节点完整且接管成功后才停止观察、启用下一张。站内导航重新连接已保留的视觉节点，不重建图层或重播动画。
- WallpaperSystem 通过 `reload()` 处理偏好与恢复，通过 `advance()` 统一手动和自动换图。`advance()` 等待候选就绪和新图淡入开始，随后释放“下一张”按钮；淡入期间允许从已提交的新图继续换到下一张，旧事务不能回写新状态。
- 换图使用原生 Web Animations 的 1.4 秒覆盖式淡入：新层持有固定图片，下层不主动淡出；每层完全显示后只回收它下方的图层，连续点击不会改变已有图层的图片或重启其动画。背景强度仍由整组图片的透明度统一控制。启动确认读取动画时间推进；250ms 启动、3000ms 完成兜底会将已解码目标收束为完整显示，不只解锁按钮。减少动态效果时即时切换，途中开启该偏好也立即收束。
- 当前照片淡化完成后重置自动轮换期限，后台补图不改变已有期限。视图分别报告呈现开始与完成，旧照片的迟到完成不能重置新照片的计时。
- 显示完成与被覆盖／销毁分别报告 `shown` 和 `discarded`，只有仍为当前照片的显示完成可重置轮换。快速连点期间视觉层可以多于两张；正常结束后仅保留最后一层，不把存储的双槽限制强加到过渡画面。
- 下载响应通过校验、解码并成功写入槽位后才能成为当前或下一张；有效同图刷新直接恢复同一份字节，不重新请求或播放淡入。
- 新文档只更新下一张所用的图片策略，绝不以视口策略变化替换正在显示的当前照片。
- 同构建导航保留壁纸视觉层；WallpaperSystem 自己把主题、背景模式和控件状态投影到目标文档，导航协调器不依赖壁纸模块。独立进度组件另按自身等待状态呈现。
- 壁纸读取请求只读取 Cron 维护的 KV 清单；Worker 处理下载上报并持有上游密钥。访客读取不得隐式刷新清单，普通 HTML 不进入 Worker。

## 绘制前恢复

当前需求同时包含两点：文字使用本站字体，不展示备用字体；连续快速刷新时，已显示的内容不能先消失成纯背景再出现。字体缓存命中、最终 ready 或进度动画存在，都不能单独证明满足这两点。

初始文档按以下顺序准备：

1. 壁纸入口继续作为独立脚本读取主题与背景偏好。
2. 原 CSS 字体声明与字体 preload 保留；字体通过原文件 URL 加载，构建禁止把小字体转成 data URL。移除字体 JS 包装、HTML 重写 middleware 和解析器重试脚本。
3. 正文及 `#initial-frame-ready` 暂存在 HTML 的 `template` 中。独立的 InitialDocument 准备脚本读取完整待提交内容，确认必需样式可用，再等待所需字体实际加载成功。
4. 条件满足后，在同一同步任务中挂载内容、恢复偏好与布局、恢复滚动并标记字体就绪，然后通知 SiteRuntime 使用 Astro 的共享脚本记录补登记已挂载内容，再初始化站点运行时。没有额外揭示动画。初始准备随文档离开取消，迟到回调还须核对原 body 身份。
5. 站内导航在脱离当前页面的目标 Document 中展开模板，确认样式和字体后才开始既有切换动画；等待期间当前内容保持显示。

浏览器的 load 事件与网站内容准备完成不同，不能据此提前提交。`rel=expect` 仅保留为支持环境下的渲染提示；字体展示条件由实际资源状态决定。首次直达文章或 404 执行同一路径，不依赖先访问首页。初始准备脚本不可用时内容不会提前显示。

[InitialDocument](../../apps/site/src/runtime/initial-document-runtime.ts) 拥有首次提交；[初始内容](../../apps/site/src/runtime/initial-document-content.ts) 只提供模板定位与挂载；[RequiredStylesheets](../../apps/site/src/runtime/required-stylesheets.ts) 确认现有样式成功或重试其原 URL。一个失败的样式请求可能仍留下不可读或空的 CSSStyleSheet，因此不能仅以对象存在判定成功；没有已解析规则时通过成功的 load 事件确认，合法空样式也可正常完成。样式在目标准备期间不提前作用于当前页面。识别同一资源只忽略本站添加的 `style-retry` 参数；目标链接沿用已恢复链接的实际 href，使 Astro 保留原样式节点及其中的字体重试规则，其他查询参数和文件版本仍参与匹配。

模板中的静态 HTML 仍由 Pagefind 建立索引，完整构建与搜索回归确认其可用。首次挂载后的搜索、页面岛、滚动与锚点另有浏览器回归。上述结果不代表原生连续刷新没有背景帧；连续刷新像素断言与真实 F5 仍有失败，D04 保持未完成。

## 必需字体

- 字体声明仍来自全局 CSS，Latin 自托管、中文按 unicode-range 分片，代码、斜体与 KaTeX 按内容选择。
- `prepareRequiredFonts(fontDocument, declarationDocument, options)` 检查所需家族真实存在及 FontFaceSet.load/check 的结果；字体已可用时同步完成，缺少时持续等待。
- 字体失败后每隔 500ms 重新请求原 CSS 声明的资源，不使用备用字体或固定超时放行；失败响应的重试 URL 带递增参数。
- 首次文档保持内容未提交；站内导航和搜索结果等待时保留上一份已提交内容。可替代任务使用所属 AbortSignal，取消后停止后续重试，迟到结果不能提交。
- 搜索结果片段齐备后，原数据响应超时不再取消字体准备；字体等待没有固定截止时间。
- 不把缓存命中、历史访问记录或 FontFaceSet.ready 单独当作成功证明。测试直接中止原字体文件、返回错误状态或无效字节，并核对实际字体及标题宽度。

资源等待过久时的浏览器画面行为与应用提前标记 ready 是不同问题；前者不能成为不实现字体必要条件的理由，也不能用字体断言通过宣称连续刷新已经解决。验证位置：[required-resource-retry](../../tests/fonts/required-resource-retry/README.md)、[D04](../audits/remaining-items.md#d04桌面刷新时整页短暂闪黑)。

## 页面生命周期

- Solid 岛使用框架 mount/unmount；
- 简单 DOM 增强由页面控制器或自定义元素拥有，按现有生命周期选择，不强制改成另一种组件形式；
- 跨页控制器由 SiteRuntime 组合，文档结束时释放；
- 页面控制器统一由 PageRuntime 挂载和销毁。图片查看器、图形聚焦等功能为及时关闭自身浮层，可在自身生命周期内订阅公开导航事件并严格解绑，不接管全局导航；
- 页面岛不能注册永不释放的 document/window 监听；
- 不保留 `claimClientRuntime(name)` 这种按字符串抢占实例的注册表；
- 不模拟 `site:before-swap`、`site:after-swap`、`site:page-load` 第二套生命周期。

## 错误与降级

| 故障                         | 行为                                                     |
| ---------------------------- | -------------------------------------------------------- |
| ClientRouter 获取/解析失败   | 原生文档导航                                             |
| 新导航覆盖旧导航             | 框架 signal 取消旧准备，旧事务不能提交                   |
| 导航或动态内容的必需字体失败 | 保留已提交内容，不提交目标；可替代事务仍可取消           |
| local/session/history 不可用 | 使用安全默认值，不阻塞完整 HTML                          |
| 页面岛加载失败               | 保留 SSR 正文、图注、链接和明确静态回退                  |
| 构建代际不一致               | 保存状态并执行完整文档导航                               |
| 其他必要脚本失败             | 按其初始化边界报告；不能以进度线存在证明内容可见         |
| 浏览器不支持 `rel=expect`    | 仍按真实资源就绪提交模板内容；原生刷新画面连续性另行验收 |
| View Transition 不可用       | 使用当前动画 fallback；减少动态效果时按相应偏好处理      |

## 禁止重新引入的模式

- 第二个路由器或 head 管理器；
- 以字符串名称连接的全站事件总线；
- 同一状态同时存在 URL、store、DOM dataset 和 storage 四个相互回写的权威副本；
- 页面级巨型 controller 扫描整个文档并认领所有组件；
- 用固定 timeout 代替字体的真实就绪信号；
- 用 `visibility`、`opacity` 或覆盖层隐藏整页内容来等待资源；字体准备不能以刷新时清空已显示内容为代价；
- 为测试方便暴露生产全局对象；
- 为少量复用提前建立插件系统、service locator 或通用状态框架。

## 验证要求

- 导航状态机、history codec、存储失败和过期事务使用单元测试；
- ClientRouter 适配器使用最小浏览器集成测试；
- 壁纸连续性、目标 Header 语义、局部视图、字体准备、快速导航和复合滚动使用行为/视觉测试；不把整个 Header 的节点身份当成持久化契约；
- 连续快速刷新必须覆盖前一次加载尚未完成就再次刷新，关联旧文档最后画面、新文档首次绘制和字体就绪状态；分别验证不出现备用字体、已显示内容不退回纯背景。不能用单次刷新最终 ready、FCP 后几帧稳定或站内导航通过代替；
- 异步交互覆盖正常完成、替代或取消、失败或销毁后的迟到结果，以及重复操作后的资源上界；
- 优先断言用户结果与公开 DOM 语义；公开观测不足时，允许最小、集中、只读且注明版本耦合的测试探针，升级依赖时复核。例如 [Plotly 相机探针](../../tests/research/plotly-camera.ts) 与 [Astro 公告范围测试](../../tests/navigation/route-announcer-scope/README.md)。这不允许为测试新增生产调试全局对象；
- 案例说明记录触发条件、验证范围与盲区。自动化通过不代表主观视觉体验或真实屏幕阅读器输出已经验收；
- 新模块必须能说明职责、公共接口和依赖方向，防止局部修复扩张成新的全局单体。
