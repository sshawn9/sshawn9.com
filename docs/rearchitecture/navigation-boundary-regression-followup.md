## 可复用的发现方法

先检查状态与生命周期边界，再把疑点变成可重复的浏览器实验，而不是只重复运行已有测试：

1. **状态归属**：地址栏与当前显示内容暂时不同步时，操作以谁为准？一个事实是否有多个写入者？
2. **取消与替代**：所有导航是否都经过所监听的事件？取消后，队列、Promise 和晚到回调是否仍会提交？
3. **失败与销毁**：功能已失败或页面已销毁后，是否仍宣称可以处理请求、更新 URL 或渲染？
4. **重复操作与清理**：原来依靠整页替换清理的节点、监听器和任务，在保留页面后是否仍有明确生命周期？资源数量是否保持有界？

具体流程：阅读相关 diff 和实际依赖版本源码 → 写出可证伪的疑点 → 用请求阻塞、同帧操作或重复操作复现 → 记录可观测结果 → 将已确认行为转为回归测试。

测试覆盖应包括正常完成、未完成时再次操作、取消/失败/销毁后的晚到回调，以及重复操作后的资源边界。通过率不能代替这些状态与操作顺序的覆盖。

## 已确认问题与待补测试

### A. 慢速后退期间，博客标签请求使用了错误页面的 URL

复现步骤：

1. 从 `/en/about/` 通过站内导航进入 `/en/blog/`。
2. 阻塞后退目标 `/en/about/` 的 HTML fetch，执行浏览器后退。
3. 确认地址栏已指向“关于”，但博客仍在屏幕上；此时点击 Git 标签。

实际结果：进入 `/en/about/?tag=git`，博客操作被应用到了其他页面的地址。

原因：`requestViewUpdate()` 使用 `window.location` 作为请求基准，而历史遍历会在旧页面退场之前改变地址栏。`replaceViewUrl()` 的遍历保护不能覆盖标签请求。这证明当前入口的边界不完整，不代表已证明该缺陷只在本次改动后出现。

自动化方法：在现有 Playwright 中用 `page.route()` 和显式响应释放控制这个时间窗口，确认旧博客仍可见后再操作；不靠长时间 sleep 猜测时序，响应必须在 `finally` 中释放。

必须成立的断言：博客标签不能写到其他页面的 URL；完成后的内容、URL 与历史项必须一致。

**本轮行为取舍**：用户要求修复后，本轮明确采用“仍可操作页面上的新点击作为最新意图”，基于该页面已提交的 URL 处理并取代未完成的后退。不禁用控件，不吞掉点击。

修正边界：导航层保存一个已提交页面 URL，区别于浏览器提前切换的目标地址；仅在地址与已显示页面对应时持久化自有滚动快照。遍历完成后，用既有快照恢复根与嵌套滚动。没有第二套历史栈，也不读写 Astro 私有历史索引；不承诺框架自身的私有滚动缓存未变化，验收对象是本站完整快照和实际可见位置。

### B. 锚点导航未能取消旧的标签队列

复现步骤：同一 JavaScript 任务内，依次点击 Astro 标签、Git 标签和真实的“跳到主内容”链接。

实际结果：地址立即变为 `/en/blog/#main-content`，随后被旧队列覆盖为 `/en/blog/?tag=astro&tag=git`。连续三次得到相同结果。

原因：队列主要依赖 `astro:before-preparation` 清理，但 Astro 7.1.6 的部分锚点导航直接走快速路径，不触发该事件；已有 abort 处理没有同步取消剩余队列。

自动化方法：用 `page.evaluate()` 构造同帧点击，但仍激活真实链接、真实路由，不用手写 `pushState` 模拟导航。覆盖“不经过准备事件”的替代导航。

断言：新锚点导航完成后，已取消的请求不能再次提交、移除 hash 或追加过期历史项。应等待相关异步工作完成后验证最终状态，不能仅捕获地址栏短暂正确的一刻。

### C. 局部导航线性积累隐藏的页面公告节点

复现步骤：在同一个博客文档中连续切换标签八次，每次局部导航完成后统计 `.astro-route-announcer`。

实际结果：节点数量为 `0 → 1 → … → 8`，全部被 CSS 隐藏；真正换页之前不会清理。

原因：保留 body 的局部更新仍经过 Astro 的 `onPageLoad()` / `announce()`。Astro 7.1.6 每次追加新节点，本站 CSS 只处理可见性，没有管理节点生命周期。其 60 ms 文本写入定时器会结束，不能把它误报为永久累积的活动定时器。

自动化方法：多次局部提交后检查公告资源数量保持有界，同时保留“局部不播报整页切换、真正跨页恢复正常公告”的测试。节点创建在 `astro:page-load` 分发之后，采样必须覆盖这一实际完成顺序。

断言不要只检查 `display: none` 或第一次导航的数量。清理应集中在明确的 Astro 适配边界；不要为掩盖该问题扩张为全站观察器或另一套公告系统。自动化不能完全替代真实读屏器验收。
