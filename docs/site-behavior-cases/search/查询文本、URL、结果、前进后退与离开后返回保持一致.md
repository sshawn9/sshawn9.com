# 案例：查询文本、URL、结果、前进后退与离开后返回保持一致

### 场景

用户连续修改查询、打开结果、返回搜索页，或使用浏览器历史导航。

### 正确行为

- 稳定态中，输入文本、规范 URL 参数和可见结果表达同一查询。
- 更新查询的短暂过渡中，输入和 URL 可以先表达新查询，而可见卡片、数量和查询说明仍表达上一轮已提交查询；等待较长时，邻近状态明确标注更新中。
- 清空输入时，URL 和可见结果立即清空；不允许等待防抖或网络任务完成。
- 有意义的查询变化按既定历史策略记录，前进后退恢复对应状态。
- 离开搜索页再返回时，查询和结果恢复到离开时的有效状态。

### 禁止状态

- 稳定后地址变化但输入框或结果仍属于旧查询；或长时间等待却没有更新提示，使用户误以为当前列表已是新查询的结果。
- 返回页面只恢复输入文本，不恢复结果。
- 恢复使用离开后产生的过期全局状态覆盖 URL。

### 验收

1. 输入多组查询并记录每步 URL、文本与结果摘要。
2. 打开结果后返回，再使用多次前进和后退。
3. 对每个历史点核对三类状态完全一致且无中间闪回。
