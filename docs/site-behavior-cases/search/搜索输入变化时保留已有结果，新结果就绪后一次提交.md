# 案例：搜索输入变化时保留已有结果，新结果就绪后一次提交

### 场景

用户修改查询，新一轮搜索需要异步计算或加载索引分片。

### 正确行为

- 首次加载较慢且尚无可显示结果时，可使用限定在结果区的骨架；快速返回不强制显示加载占位。
- 已有结果后刷新查询，旧卡片和旧数量继续可见、可操作；不得为每一轮刷新替换成骨架、空列表或隐藏列表。邻近状态提示可延迟说明正在更新。
- 输入可立即显示正在键入的查询，而可见结果、数量和查询说明仍短暂属于上一次已提交查询；新搜索超过短暂等待后显示更新提示，新查询准备完毕后三者一起提交。
- 新结果的摘要、匹配高亮和章节内容随当前查询更新；实现可以整批替换卡片，不要求保留 DOM 节点身份。
- 输入、Header、背景、导航和页脚保持可见稳定；骨架不得扩散到整个页面。
- 输入变更立即使此前任务失效，包括防抖等待期间；中文输入法组合输入不提交中间结果。清空则立刻清除卡片和 URL，旧任务不得回写。
- 新卡片内容与所需字体在显示前准备完成。屏外结果按批次加载，已显示的卡片不回退成骨架。

### 禁止状态

- 新旧结果同时作为两套卡片出现，造成重影或焦点落入已经过期的结果。
- 刷新时结果区完全空白、页面高度无约束坍塌或整个页面被隐藏。
- 结果先替换，数量或状态文案稍后更新；或把仍显示的旧结果标成新查询的结果。
- 较慢的旧请求在新请求后完成并回写页面。

### 验收

1. 人为延迟不同查询并快速连续输入。
2. 分别逐帧记录首次加载的骨架，以及已有结果时的输入、旧卡片、旧数量、状态提示和最终新结果。
3. 核对首次骨架与结果卡片的主要几何，并确认刷新没有空窗或整页跳变。
4. 确认没有两套卡片混合、迟到结果覆盖，且清空后在途任务不能回写。
5. 阻塞新结果所需字体，确认旧结果仍可见；释放字体后才提交新结果。
6. 检查摘要高亮更新，以及方向键、输入法和焦点恢复；有焦点的链接仍在新结果中时恢复到该链接，否则回到输入框。
