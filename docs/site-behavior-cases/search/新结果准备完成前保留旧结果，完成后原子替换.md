# 案例：新结果准备完成前保留旧结果，完成后原子替换

### 场景

用户修改查询，新一轮搜索需要异步计算或加载分片。

### 正确行为

- 旧结果在新结果完整准备好之前保持可见，页面以克制方式表达正在更新。
- 新结果、数量和空状态作为一个整体原子替换。
- 迟到的旧查询结果不得覆盖更新后的查询。

### 禁止状态

- 每次按键先清空结果，造成页面高度持续抖动。
- 结果先替换，数量或状态文案稍后更新。
- 较慢的旧请求在新请求后完成并回写页面。

### 验收

1. 人为延迟不同查询并快速连续输入。
2. 逐帧记录旧结果、忙碌状态、新结果和数量。
3. 确认没有空窗、混合状态或迟到结果覆盖。
