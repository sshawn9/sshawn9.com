# 案例：版本比较只选择一个对照版本，并按需加载单栏或双栏界面

### 场景

用户希望把当前版本与一个历史版本进行比较。

### 正确行为

- 一次只选择一个对照版本，当前版本作为明确的另一端。
- 未开启比较时不加载重型比较界面；开启后按比较主区域的实际容器宽度自动选择单栏或双栏呈现。
- 用户手动选择单栏或双栏后，该选择在当前比较页存活期间优先于自动布局；重新进入时再由实际容器宽度决定默认值。
- 禁用 JavaScript、比较资源失败或重型模块加载失败时，仍显示两个版本的永久链接和有意义的静态说明。
- 切换对照版本保留文章上下文，不重建无关 Sidebar 和正文能力。

### 禁止状态

- 允许多个对照版本同时叠加，导致语义和界面失控。
- 所有文章首屏都预载比较运行时代码。
- 仅用视口宽度决定布局，忽略 Sidebar 后实际容器宽度。
- 自动响应在用户明确选择布局后继续覆盖该选择。
- 失败时只留下空白 diff 容器，或让用户失去访问两个完整版本的入口。

### 验收

1. 在多版本文章开启、切换和关闭比较。
2. 改变比较主区域与视口宽度，核对自动布局使用实际容器宽度；再手动选择布局并确认自动响应不覆盖。
3. 禁用 JavaScript并模拟资源失败，确认两个版本永久链接和静态说明仍可使用。
4. 记录网络和组件实例，确认比较能力只在比较路由按需加载且无关状态保留。
