# BCP-002：文章页面的阅读顺序与视觉布局解耦

- 状态：已批准
- 提出日期：2026-08-29
- 批准日期：2026-08-29
- 当前是否改变契约：是
- 当前是否允许实现：是

## 批准范围

批准采用方案 A：文章文档与辅助技术顺序固定为“文章头 → 文章信息、目录与版本支持 → 正文”。桌面端继续显示“正文在左、支持 Sidebar 在右”，由 CSS Grid 放置实现；移动端按文档顺序在正文前显示紧凑的支持模块。

这项批准改变的是此前未明确规定的文档阅读顺序，不授权改变文章的桌面视觉构图、正文内容、Sidebar 能力或目录交互。

## 受影响案例

- `article-sidebar-toc-versions/无-JavaScript-时文章信息、完整目录和正文仍可阅读.md`
- `article-sidebar-toc-versions/右侧-Sidebar-默认展开，文章信息、目录、版本与比较均为其子模块.md`
- `site-structure-responsive-visual/同一响应式布局在桌面、移动端与-iPad-浏览器中保持完整可用.md`

## 当前行为

既有案例要求文章信息、目录、版本和正文都能在无 JavaScript 时使用，但没有规定它们在线性 DOM 与辅助技术中的先后顺序。旧实现主要从桌面左右构图反推结构，移动端和线性阅读的顺序缺少单一契约。

## 建议行为

- 线性顺序固定为文章头、支持信息、正文。
- 桌面用 CSS Grid 把同一结构视觉排成正文左、Sidebar 右，不让视觉位置决定 DOM 顺序。
- 移动端在正文前提供紧凑的文章信息、目录和版本入口。
- 正文保持单一 DOM 实例；响应式切换和 Sidebar 操作不得搬运或重建正文。

## 决策理由

- 屏幕阅读器、键盘线性浏览、阅读模式和无样式文档先获得标题与理解正文所需的发布日期、目录和版本上下文，再进入可能很长的正文。
- 桌面视觉位置不需要决定 DOM 顺序；Grid 可以在不复制正文、不使用脚本搬运节点的情况下保持正文左、Sidebar 右。
- 移动端不必先读完整长文才能访问目录和版本入口，首段内容仍紧随一个紧凑、可折叠的支持区出现。
- 正文只存在一个权威 DOM 实例，Sidebar 折叠、调宽或响应式切换不得重建正文及其中的交互岛。

## 用户可观察影响

- 桌面视觉与既定方案一致：文章头横跨内容区，正文位于左列，支持 Sidebar 位于右列。
- 移动端依次显示文章头、紧凑文章信息、目录入口与版本入口，然后显示正文。
- 禁用 CSS 或使用线性阅读工具时，顺序仍是文章头、支持信息、正文。
- 响应式切换不会移动或重建正文节点。

## 被拒绝的取舍

把正文放在支持信息之前虽然更接近桌面视觉的源码直觉，但会让线性阅读者越过整篇长文后才能访问目录和版本。依赖 JavaScript 在不同断点搬运节点会引入节点身份、焦点、生命周期和首帧竞态，因此也不采用。

## 证据要求

1. 禁用 JavaScript 后，完整文章头、支持信息、目录链接、版本链接和正文均存在。
2. DOM 顺序明确断言文章头先于支持区，支持区先于正文。
3. 桌面截图证明正文左、Sidebar 右且视觉构图未改变。
4. 移动端截图和键盘/辅助技术顺序证明支持区位于正文前。
5. 响应式切换、Sidebar 折叠与调宽不重建正文节点。

## 回滚

若真实辅助技术或跨浏览器验证发现该顺序产生无法接受的问题，必须提出新的行为变更并重新比较线性阅读顺序；不得在实现中静默恢复正文优先、脚本搬运节点或两套正文。CSS Grid 的视觉放置可以独立回滚，不应要求修改内容模型、版本路由或正文结构。
