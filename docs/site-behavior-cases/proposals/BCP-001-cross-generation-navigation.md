# BCP-001：跨部署代际的导航边界

- 状态：已批准
- 提出日期：2026-08-28
- 批准日期：2026-08-29
- 当前是否改变契约：是
- 当前是否允许实现：是

## 批准范围

批准采用方案 A：同一构建代际继续保持持久外壳；跨构建代际保存可序列化状态后执行完整文档导航。

本批准只放宽跨代际导航时的 DOM 身份与瞬时内存连续性，不授权改变同代导航、视觉、动画或交互语义。生产站尚未实施；正式 v2 必须满足本文证据要求后才能切换流量。

## 受影响案例

- `refresh-navigation-lifecycle/站内导航只替换页面出口，站点外壳保持同一实例.md`
- `refresh-navigation-lifecycle/站内页面切换保留既有动画，不退化为整页重载或突变.md`
- `refresh-navigation-lifecycle/同一页面硬刷新时，首个可见帧即为最终稳定画面.md`
- `browser-cache-artifacts/内容更新后浏览器获取新-HTML，并由新哈希引用更新静态资源.md`
- `browser-cache-artifacts/Pagefind-入口与分片按部署版本保持内部一致.md`

## 当前行为

所有站内导航都要求只替换页面出口，站点外壳保持同一 DOM 实例。现有案例没有区分导航前后是否属于同一次部署。

## 建议行为

- 同一构建代际内的普通站内导航继续保持持久外壳同一实例、既有动画和状态。
- 目标文档构建 ID 与当前页面不一致时，客户端先保存可序列化状态，再执行原生文档导航。
- 新文档必须在首个可见帧前恢复主题、背景、布局偏好、URL 状态和可恢复滚动位置。
- 除跨代际、不可安全接管或明确错误回退外，不允许用完整导航代替正常的持久导航。

## 理由

部署之后，旧标签页可能仍运行旧 JavaScript 和旧 CSS。强行把新 HTML 接入旧运行时会形成跨代际组合，产生旧代码控制新 DOM、资源已被删除或搜索分片不一致等问题。把部署边界视为导航事务边界，可以换取确定的一致性和可回滚性。

## 用户可观察影响

- 部署恰好发生在用户浏览期间时，下一次导航可能成为一次完整文档请求。
- 无法序列化的瞬时组件内存可能重置；URL、持久偏好和明确纳入状态账本的滚动/交互状态应恢复。
- 浏览器可能显示原生加载指示，但不得出现无样式旧页、错误正文、双份内容或布局跳变。

## 不改变行为的替代方案

长期保留每个部署的全部旧资源，并让旧运行时只导航到同代际 HTML。这需要代际路由、旧 HTML 保留和更复杂的缓存键，平台与维护成本明显更高，也会扩大回滚和缓存失配面。

## 证据要求

1. 用两个不同构建 ID 的本地产物模拟部署切换。
2. 证明同构建导航保持外壳节点引用。
3. 证明跨构建导航不会执行旧运行时对新文档的接管。
4. 连续录制跨构建导航，检查首帧、主题、背景、字体和布局。
5. 验证 URL、主滚动和嵌套滚动恢复；明确列出不可恢复的瞬时状态。
6. 在 Cloudflare 不可变 Preview URL 和稳定分支 URL 上复核。

## 当前 POC 证据

2026-08-29 的隔离 Astro POC 已完成前五项的本地证据：两个真实构建使用不同 build ID 和资产目录；A 运行时拿到 B 文档后没有触发 `before-swap`，而是完成一次原生文档导航；B 代内后续导航继续保持持久外壳；目标 ID 缺失时同样安全降级。跨旧文档历史边界返回时会再次发生原生文档请求，POC 已恢复主题、壁纸、主滚动和嵌套滚动。

连续帧测试在 B 代样式延迟 460 ms、字体延迟 680 ms 时同时记录 DOM 动画帧、浏览器 screencast、filmstrip 和视频；可呈现帧只包含完整 A 或完整 B，B 的首个可呈现帧字体状态为 `loaded`。这项证据仅来自本地 Chromium；Firefox/Safari 和 Cloudflare Preview 复核仍是生产切换门槛，但不再作为继续扩展 POC 的理由。

正式 v2 的 `apps/site-v2/tests/e2e/runtime.spec.ts` 进一步在真实 ClientRouter 上改写一次目标 HTML fetch 的构建 ID，证明旧外壳不会被持久到不匹配的目标文档；同一套测试同时覆盖同代外壳身份和快速取消。双真实构建与连续帧仍以隔离 POC 证据为准，平台复核留在 M5。

## 回滚

构建版本门可以独立关闭，恢复当前所有站内请求都交给客户端路由的行为。回滚不应要求修改内容模型或页面结构。
