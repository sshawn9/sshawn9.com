# BCP-003：采用 Pagefind 标准加载与 Escape 语义

- 状态：已批准
- 提出日期：2026-08-29
- 批准日期：2026-08-29
- 当前是否改变契约：是
- 当前是否允许实现：是

## 受影响案例

- `search/Escape-采用搜索输入的标准清空语义，并同步完整查询状态.md`
- `search/搜索期间结果区显示稳定骨架，完成后提交当前查询结果.md`
- `search/从搜索结果进入页面再返回时，回到同一查询和结果状态.md`

## 当前行为

- Escape 只取消输入框焦点，保留查询、URL 和结果。
- 新查询准备期间继续显示旧查询结果，完成后原子替换。
- 返回搜索页时，首帧必须直接显示此前结果，不允许出现加载占位。

这些要求迫使旧实现拦截 Pagefind 的输入语义、克隆第三方结果 DOM、维持双层结果和修补第三方样式，显著扩大了生命周期和状态所有权。

## 建议行为

- 搜索输入采用 Pagefind 标准 Escape 语义：清空查询并重置搜索；URL、摘要和结果同步归零。
- 新搜索和返回恢复期间，结果区可以用与最终卡片几何相近的 Pagefind 骨架明确表示加载。
- 骨架只限结果区；Header、输入、背景、导航和页脚保持稳定。
- 结果完整准备后一次提交；失败在有限时间内进入明确错误和静态回退。
- 不再克隆旧结果 DOM、建立双层结果缓冲或读取 Pagefind 私有结构。

## 用户可观察影响

- 按 Escape 会清空当前搜索，而不是只取消焦点。
- 修改查询后，旧结果会被骨架替代；冷索引时骨架可能清晰可见，热缓存时可能很短。
- 从结果返回时，查询和 URL 立即正确，但结果区可以短暂显示骨架后恢复结果。
- 不会出现整页空白、错误旧结果、无样式内容或无限加载。

## 证据要求

1. Escape、清空按钮和删除全部文本都同步更新输入、URL、摘要和结果。
2. 慢索引和慢分片下，只有结果区显示几何稳定的骨架，站点外壳不移动。
3. 快速连续查询时，迟到结果不能覆盖当前查询。
4. 从结果返回时，查询和 URL 首帧正确；骨架只出现于结果区，结果完成后恢复滚动。
5. 拦截组件脚本、入口索引和结果分片，分别验证有限错误与静态入口。
6. 实现只使用 Pagefind 公共组件、配置和事件，不读取或复制其内部结果树。

## 回滚

若真实设备证明骨架造成不可接受的视觉抖动，应先调整官方 placeholder 模板、结果区几何和防抖参数。只有这些手段仍不能满足体验时，才提出新的行为变更讨论旧结果缓冲；不得直接恢复旧版 DOM 克隆和私有样式补丁。
