# 案例：带标签筛选状态硬刷新时，首帧原子恢复完整筛选结果

### 场景

用户已选择一个或多个标签，URL、左侧选中状态、筛选结果、文章卡片标签高亮、文章数量和分页彼此一致，随后硬刷新页面。

### 正确行为

- 硬刷新会重建文档，但首个可见帧必须直接呈现完整的筛选终态。
- 左侧选中标签、筛选后的文章、文章卡片标签高亮、数量、分页和 URL 必须同时一致。
- 水合只能接管交互，不得改变已经可见的内容、样式和布局，也不得重新播放进入动画。
- Header、导航栏、壁纸和整体页面结构不能闪烁或跳动。
- 标签 Sidebar 的宽度、折叠状态和几何位置必须直接采用保存值，不能先显示默认状态。
- 无标签时不闪、有标签时闪属于错误；筛选状态不能降低刷新稳定性。
- 站内导航属于另一生命周期：Header、导航和壁纸等持久外壳还必须保留原 DOM 实例。

### 禁止状态

任一可见帧出现以下情况即失败：

- 全部文章先出现，再变成筛选结果。
- 左侧标签先未选中，随后亮起。
- 左侧标签已经选中，文章卡片标签随后才亮起。
- 文章列表消失后重现。
- 整个 body 被隐藏，导致导航、壁纸和页脚一起空白。
- 水合后重新播放文章列表动画。
- 最终状态正确，但中间出现过错误状态。

### 验收

1. 选择标签后，分别使用冷缓存和温缓存硬刷新。
2. 将博客交互脚本延迟约 500ms，暴露服务端输出到水合完成之间的过程。
3. 从首个可见帧开始连续记录左侧标签、文章集合、文章卡片标签、数量、分页、Header、壁纸和 Sidebar 几何。
4. 任一帧违反上述行为即失败，不能只检查最终 DOM 或最终截图。
5. 最后使用系统安装的 Chrome 实际刷新确认没有可见闪烁。
