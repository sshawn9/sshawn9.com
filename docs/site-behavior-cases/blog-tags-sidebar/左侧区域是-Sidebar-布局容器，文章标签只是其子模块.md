# 案例：左侧区域是 Sidebar 布局容器，文章标签只是其子模块

### 场景

博客桌面布局当前包含标签目录，未来可能加入其他浏览辅助模块。

### 正确行为

- Sidebar 自己负责宽度、折叠、边界、内部滚动和与正文的布局关系。
- 标签目录只负责标签内容与筛选，不拥有整个 Sidebar 的布局控制权。
- 新增 Sidebar 子模块时无需修改文章列表的核心结构或标签状态机。

### 禁止状态

- 把折叠、调宽或整体滚动逻辑挂在标签列表内部。
- 标签模块卸载后 Sidebar 的边界和布局一起消失。
- 文章列表直接依赖标签组件的内部状态才能计算主栏宽度。

### 验收

1. 检查 DOM 与可访问结构，确认 Sidebar、子模块和正文层级明确。
2. 临时移除标签内容，确认 Sidebar 布局契约仍成立。
3. 验证折叠、调宽由布局控制器处理，筛选仍由标签模块处理。
