# 案例：最终截图一致不能证明刷新稳定，必须检查从首帧到水合完成的全过程

### 场景

刷新后的最终 DOM 和截图正确，但用户报告刷新期间出现闪烁、跳动或错误状态。

### 正确行为

- 验收窗口从首个可见帧开始，持续到水合、字体和必要状态接管完成。
- 同时观察可见性、几何、内容、样式和状态语义，而不只比较起止坐标。
- 任一中间错误帧都记为失败，即使最终画面完全正确。

### 禁止状态

- 只等待 networkidle 后截图并据此宣称没有闪烁。
- 用刷新前后元素坐标相等反驳刷新期间的位移。
- 通过缩短观察窗口或隐藏页面让自动化“通过”。

### 验收

1. 对目标页面录制从导航确认到完全稳定的逐帧过程。
2. 采集关键元素每帧的可见性、边界矩形和语义状态。
3. 将过程证据与最终 DOM 断言分别报告，任一过程违规即失败。
