# 案例：首帧问题使用冷缓存、温缓存与人为延迟脚本分别暴露

### 场景

刷新稳定性可能只在首次下载、缓存命中或客户端接管窗口足够长时暴露。

### 正确行为

- 冷缓存覆盖资源首次获取，温缓存覆盖高速度下的竞态。
- 人为延迟相关脚本扩大服务端输出到水合之间的窗口，而不改变被测业务状态。
- 三类结果分别记录，不能由其中一种通过替代其他场景。

### 禁止状态

- 只在开发者已预热缓存的浏览器中刷新一次。
- 延迟所有资源导致测试变成与真实问题无关的全站故障。
- 看到冷缓存通过就跳过温缓存竞态，或反向处理。

### 验收

1. 为同一目标建立冷缓存、温缓存和定向延迟三组测试。
2. 每组从首帧记录到接管完成，并使用相同禁止状态判定。
3. 比较差异并定位具体资源或生命周期阶段。
