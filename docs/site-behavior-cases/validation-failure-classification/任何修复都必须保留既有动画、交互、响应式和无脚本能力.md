# 案例：任何修复都必须保留既有动画、交互、响应式和无脚本能力

### 场景

为解决闪烁、性能、布局或状态恢复问题，需要修改共享组件和生命周期。

### 正确行为

- 先列出与修改区域相邻的既有正确行为，再确定回归范围。
- 修复保留用户主动动画、完整交互、各容器宽度布局和无 JavaScript 基础能力。
- 必须改变既有行为时，作为独立设计选择说明影响并取得确认。

### 禁止状态

- 为消除加载动画而连用户主动过渡一起删除。
- 为简化状态恢复取消调宽、键盘或移动端能力。
- 用客户端完整重建替换原有服务端可读内容。

### 验收

1. 建立修改前的相关行为清单和代表测试。
2. 修复后逐项验证主动、恢复、响应式、输入方式及无脚本路径。
3. 对任何行为变化提供明确证据，未经确认不得当作修复附带结果。
