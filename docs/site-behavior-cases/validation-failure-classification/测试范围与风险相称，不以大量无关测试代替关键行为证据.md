# 案例：测试范围与风险相称，不以大量无关测试代替关键行为证据

### 场景

改动从单一文案到共享生命周期或部署规则，风险范围差异很大。

### 正确行为

- 根据改动触及的契约选择静态检查、单元、集成、E2E、逐帧和人工测试。
- 优先验证最可能失败且后果最严重的关键路径。
- 扩大范围必须有共享机制或风险证据，不用测试数量制造虚假信心。

### 禁止状态

- 小文档修改运行全部昂贵 E2E，却不检查链接和结构。
- 共享首帧控制器变更只跑类型检查。
- 报告“通过很多测试”但没有覆盖用户看到的真实现象。

### 验收

1. 在测试前写明改动范围、关键契约和未覆盖风险。
2. 执行最小充分集合，并记录每项测试支持的具体结论。
3. 若自动化无法覆盖真实现象，补充目标人工验证而不是堆叠无关套件。
