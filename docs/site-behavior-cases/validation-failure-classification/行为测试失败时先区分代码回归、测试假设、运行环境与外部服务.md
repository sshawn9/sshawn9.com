# 案例：行为测试失败时先区分代码回归、测试假设、运行环境与外部服务

### 场景

一组 E2E 或行为测试大量失败，失败可能来自产品代码、测试本身、启动环境或外部依赖。

### 正确行为

- 先读取首个代表性失败的实际页面、日志、请求和断言前提。
- 将失败分类为代码回归、测试假设失效、运行环境问题或外部服务问题。
- 修复对应根因后运行与风险匹配的最小集合，再扩展回归范围。

### 禁止状态

- 大量测试失败仍宣称功能已经完成。
- 为让测试变绿随意改产品，或为保护产品随意删除测试。
- 不检查服务是否正确启动就分析页面代码。

### 验收

1. 从失败集中选择不同症状的代表样本收集完整证据。
2. 对每项记录分类依据和所需处置。
3. 修复后先复跑对应样本，再运行相关套件确认没有隐藏同类问题。
