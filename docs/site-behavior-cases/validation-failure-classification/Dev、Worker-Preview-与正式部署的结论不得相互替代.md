# 案例：Dev、Worker Preview 与正式部署的结论不得相互替代

### 场景

某个行为只在本地 Dev、实际 Worker Preview 或上线 Production 中出现。

### 正确行为

- 每个环境使用其实际运行入口和资源管线独立验证。
- 结论注明环境、构建模式、缓存和访问路径。
- 一个环境通过只能说明该环境，不得否认另一环境的可复现问题。

### 禁止状态

- 用 Production 不跳动否认 Dev 中真实存在的生命周期缺陷。
- 用户明确在 Worker Preview 复现，却擅自转去 Dev 并改变问题定义。
- 把 Astro Preview、Worker Preview 和线上流量当作同一运行时。

### 验收

1. 按报告中的真实命令或部署地址复现原环境。
2. 必要时在其他环境做对照，但分别保存结果。
3. 只有完成目标环境验证后，才能对该问题作完成结论。
