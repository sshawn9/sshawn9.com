# 案例：同一页面硬刷新时，首个可见帧即为最终稳定画面

### 场景

用户停留在任意页面和滚动位置，页面已经进入稳定状态，随后执行硬刷新。

### 正确行为

- 浏览器可以重建文档，但首个可见帧必须直接呈现刷新后应有的内容、布局、主题和保存的界面状态。
- 服务端输出、绘制前恢复与客户端接管必须使用同一状态，接管不能再做一次可见修正。
- 最终坐标相同不够；从首帧到接管完成的每一帧都必须连续。
- 字体就绪状态只协调目录、Sidebar 和交互图等几何消费者，不拥有页面表面的可见性；冷缓存准备、有限超时和降级期间均不得撤下正文、导航或页脚。
- 当前文档确认同一页面实际字形已经加载时，可以同步提交最终字体状态；检查尚未完成也不得重放整页隐藏或揭示。温缓存刷新从首帧到字体终态之间不得发生换字、位移或可见性变化。
- 已完成本地首帧事务的景观照片在同标签页刷新时直接保持；只有副本确实缺失或损坏且远程资源不可用时，才允许从完整默认背景执行一次复合淡入。任何路径都不得阻塞正文或改变布局。

### 禁止状态

- 已经稳定显示的正文、导航、Sidebar 或页脚因客户端接管短暂消失后在原位重现。
- 元素先使用默认尺寸、位置或样式，再跳到保存状态。
- 通过隐藏整个页面掩盖错误帧，却让用户等待不确定时间。
- 为等待字体、壁纸或其他网络资源而隐藏 `html`/`body`、壁纸或整个视觉根。
- 让 `loading`、`ready` 等内部字体状态直接控制正文、导航或页脚的 `visibility`、`display` 或 `opacity`。

### 验收

1. 在首页、博客页、普通文章和含交互图文章分别进行冷、温缓存硬刷新。
2. 从首个可见帧连续录制到水合完成，检查内容可见性、几何和样式。
3. 延迟客户端脚本以暴露服务端输出与接管之间的阶段。
4. 任一帧发生消失、重现或位移即失败。
