# 案例：浏览器前进后退恢复 URL 对应状态，不采用离开后的过期状态

### 场景

用户在筛选、分页、搜索、文章锚点和普通页面之间导航，然后使用浏览器前进或后退。

### 正确行为

- 页面内容、查询、选中项、主滚动与嵌套滚动共同恢复到目标历史项。
- 根文档和 Sidebar 等嵌套滚动都以目标历史项的快照为准；不能始终保留离开时当前 Sidebar 的滚动位置。
- URL 与对应历史项共同决定应恢复的页面状态。
- 恢复过程不得先显示当前页面状态，再纠正为历史状态。
- 滚动位置属于目标历史项的放置状态，必须在目标页面暴露前瞬时恢复，不得从离开页面的位置平滑滚动过去。
- 后退被新的页面操作打断时，仍显示页面的滚动位置不能覆盖后退目标的快照；再次返回目标时仍恢复它自己的位置。

### 禁止状态

- URL 已回到旧查询，但结果仍是离开前的新查询。
- 正文恢复后，Sidebar 滚动或选中项仍来自另一历史项。
- 后退被错误实现为进入与历史无关的上一页面。
- 目标页面先继承离开页面的滚动位置，再可见地滚到保存位置。

### 验收

1. 组合执行标签筛选、翻页、搜索和文章锚点跳转，并在不同历史项分别设置根文档与嵌套滚动位置。
2. 多次前进、后退并记录每一历史项的 URL、内容与滚动。
3. 从目标页面开始出现时逐帧检查，确认首帧、后续帧与终态均直接位于目标历史项位置。
4. 刷新恢复后的历史项，确认结果仍可由 URL 独立重建。
5. 给来源页和后退目标设置不同的滚动位置，打断后退后再次返回，确认目标快照与实际位置都未被来源页覆盖。
