# 案例：推送一个分支只更新该分支预览，不重复部署其他分支

### 场景

仓库存在多个并行开发分支，各自有稳定 Preview。

### 正确行为

- 分支推送只触发该分支需要的验证与预览更新。
- 其他分支的预览地址、版本和构建记录保持不变。
- main 的 Production 只由明确的 Production 工作流更新。

### 禁止状态

- 任意分支推送重新部署所有分支预览。
- 功能分支推送意外触发 Production。
- 为发现分支而在每次运行中扫描并重建全部环境。

### 验收

1. 同时准备两个分支预览并记录部署版本。
2. 只推送其中一个分支，检查工作流和平台部署记录。
3. 确认另一个分支及 Production 没有新部署或流量变化。
