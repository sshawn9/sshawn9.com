# 案例：本地开发分别提供草稿和单语文章工具，生产构建完全隔离

### 场景

作者在本地运行 `npm run dev`，需要快速查看草稿，并发现缺少英文或中文正文的文章版本。

### 正确行为

- 本地 Astro Dev Toolbar 分别注册 `Drafts` 和 `Single-language` 两个工具。
- `Drafts` 列出所有草稿版本，并提供当前界面语言下的文章入口。
- `Single-language` 按文章版本列出单语内容，明确已有语言和缺失语言，并提供中英文入口。
- 诊断必须基于尚未执行草稿过滤和语言回退的原始文章集合，不能让回退结果掩盖内容缺口。
- 正式博客 UI 不增加开发控制；生产配置和生产浏览器产物均不引用开发工具。

### 禁止状态

- `npm run dev` 启动后工具栏缺失，或草稿/单语文章入口未注册。
- 为草稿入口修改正式博客筛选状态机或页面布局。
- 将 Toolbar 客户端、诊断协议或开发集成打入 preview/production 浏览器产物。
- 为未来工具预先建立通用插件平台、注册中心或无实际消费者的抽象层。

### 验收

1. 从干净进程运行 `npm run dev`，确认 Astro 页面和 Worker API 均可用。
2. 在系统 Chrome 分别打开 `Drafts` 和 `Single-language`，核对结果及其链接。
3. 构建 preview，确认草稿存在、页面 `noindex` 且 Toolbar 不存在。
4. 构建 production，确认草稿和 Toolbar 均不存在。
