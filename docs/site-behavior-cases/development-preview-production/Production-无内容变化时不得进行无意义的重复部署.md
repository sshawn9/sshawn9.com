# 案例：Production 无内容变化时不得进行无意义的重复部署

### 场景

工作流、文档或仅影响 Preview 的内容变化不会改变 Production 产物。

### 正确行为

- 发布流程根据可验证的 Production 产物或内容变化决定是否部署。
- 无变化时明确跳过，不创建新 Production 版本和无意义缓存扰动。
- 跳过判定可审计，并不妨碍真正配置或运行时变化发布。

### 禁止状态

- main 每次推送都无条件生成相同 Production 部署。
- 仅比较提交路径而漏掉会影响产物的间接配置变化。
- 跳过逻辑基于不稳定时间戳，导致相同内容仍被判为变化。

### 验收

1. 分别提交仅影响文档、仅影响 Preview 和影响 Production 的变化。
2. 检查产物判定、部署记录与新版本数量。
3. 重跑同一已验证工作流，确认结果确定且真正变化不会被漏掉。
