# 案例：删除分支后历史预览交由平台保留策略处理，不自建清理系统

### 场景

开发分支完成或废弃，其稳定预览入口不再需要更新，但平台仍可能保留历史部署。

### 正确行为

- 分支删除后停止新的预览部署。
- 历史版本的保存和过期遵守平台已确认的保留策略。
- 只有出现明确合规、成本或隐私需求时才另行设计清理机制。

### 禁止状态

- 在没有真实需求时自建复杂定时清理和状态数据库。
- 假设删除 Git 分支必然立即删除平台历史版本。
- 清理脚本误删其他分支或 Production 版本。

### 验收

1. 在测试分支记录稳定地址和历史版本后删除分支。
2. 观察平台行为并对照官方保留策略。
3. 确认没有新的部署，且现有流程不承担未经要求的清理职责。
