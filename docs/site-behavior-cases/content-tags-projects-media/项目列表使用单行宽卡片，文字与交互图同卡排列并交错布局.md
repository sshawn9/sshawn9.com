# 案例：项目列表使用单行宽卡片，文字与交互图同卡排列并交错布局

### 场景

项目列表需要展示项目说明，并在确有意义时提供代表性预览，保持清晰浏览节奏。

### 正确行为

- 每个项目占一张横向宽卡片；有代表性预览时，文字和预览位于同一卡片中。
- 预览是项目显式声明的可选能力；没有真实预览的项目使用内容主导卡片，不生成装饰性假交互。
- 连续带预览卡片可交错文字与图形方向，形成节奏但不改变信息层级。
- 项目标题常态无下划线，只在悬停或键盘聚焦时显示链接反馈。
- 窄容器下按内容优先级堆叠，交互仍完整且不产生横向溢出。

### 禁止状态

- 拆成独立小卡片网格，使项目说明与预览失去归属。
- 强迫所有项目实现交互图，或用与项目无关的动画填补空位。
- 交错布局改变阅读顺序或辅助技术顺序。
- 为维持横排在移动端压缩文字、裁切图形或横向滚动。

### 验收

1. 检查有预览、无预览以及连续多个带预览项目的布局与 DOM 阅读顺序。
2. 在桌面、平板和移动容器宽度下验证重排。
3. 操作卡片内交互图，确认不会触发卡片导航或遮挡文字。
