# 案例：默认背景硬刷新不创建无意义的替换步骤

### 场景

用户关闭景观背景，页面使用内建默认背景并执行硬刷新。

### 正确行为

- 默认背景由稳定页面样式直接提供。
- 刷新过程中不存在旧层清理、新层补建或同图替换。
- 景观模式未启用时，默认背景不参与任何照片替换过程。
- 壁纸系统可以在后台异步维护当前与下一张照片，但不得改变默认背景的任何可见状态。

### 禁止状态

- 默认背景也经历淡出、替换或闪烁。
- 为统一代码路径给默认背景创建临时图片层。
- 接管后才移除一个本可不存在的占位背景。
- 后台照片准备阻塞正文、主题或默认背景显示。

### 验收

1. 关闭景观背景并多次硬刷新。
2. 检查完整帧序列中的背景、遮罩和页面亮度。
3. 确认没有临时可见层或透明度动画；后台照片请求不改变画面。
4. 在亮暗主题分别验证。
