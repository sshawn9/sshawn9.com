# 案例：景观模式硬刷新优先复用同一照片，慢资源不阻塞正文

### 场景

用户已在景观模式看到清晰照片，随后硬刷新同一页面。

### 正确行为

- 当前照片稳定显示前，把浏览器实际选择的压缩响应保存为当前标签页的首帧副本；不重新编码，也不下载未被浏览器选择的原始大图。
- 绘制前同步恢复主题、景观开关、布局、照片身份、署名和经过验证的首帧副本；`BackdropSurface` 解析时直接绘制同一张清晰照片。
- 有有效首帧副本时，它在本次文档生命周期内始终是当前照片的唯一视觉所有者；不得再次请求、解码或用远程同图接管。只有照片身份确实改变时才允许切换视觉所有权。
- 若首帧副本确实不存在或损坏，且远程照片仍不可用，立即显示结构、主题和布局完整的默认背景页面；随后由 `BackdropPresenter` 解码并执行一次正常景观复合过渡。

### 禁止状态

- 为等待装饰背景而隐藏正文、延迟整个文档或显示空白帧。
- 同一照片从模糊重新变清晰，或重复淡入造成闪亮。
- 照片与署名不同步，或首帧正确后又添加第二层相同照片。
- 重新编码图片、下载浏览器未选择的原始大图，或把图片副本写入 Worker/KV。

### 验收

1. 在照片完全清晰且首帧事务完成后连续硬刷新至少六次，确认同一照片与署名始终拥有首个可见帧且不产生过渡。
2. 从刷新提交开始连续录制到运行时就绪，检查正文可见性、背景类型、照片 ID、署名和图层数量，并确认没有同图图片请求或所有权交接。
3. 延迟或阻断图片与字体，确认首帧立即呈现完整默认页面。
4. 恢复图片请求，确认随后最多发生一次正常过渡且最终只有一个活动层。
5. 用正式 Worker Preview 与系统 Chrome 复核本地结论。
