# 案例：普通访客只读取缓存清单，不触发上游搜索或照片池刷新

### 场景

大量用户同时访问或刷新网站，照片池已经存在有效清单。

### 正确行为

- 用户请求只读取 Worker/KV 中的现有公开清单。
- 照片池更新由定时任务或明确维护路径负责。
- 访问量增加不会按访客数量消耗 Unsplash 搜索额度。

### 禁止状态

- 每次页面访问都搜索一批新照片。
- 清单稍旧便由每个全球 Worker 实例并发刷新。
- 客户端主动“下一张”触发上游搜索。

### 验收

1. 预置有效清单并连续、并发请求公开端点。
2. 统计上游搜索调用次数，预期为零。
3. 在自动轮换和手动换图时重复观察。
4. 单独触发定时维护，确认更新职责边界。
