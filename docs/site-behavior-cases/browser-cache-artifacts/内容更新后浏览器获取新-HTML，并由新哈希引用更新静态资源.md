# 案例：内容更新后浏览器获取新 HTML，并由新哈希引用更新静态资源

### 场景

网站发布包含正文、样式或脚本变化的新版本，用户浏览器保留旧部署缓存。

### 正确行为

- 稳定页面 URL 重新验证并获得新 HTML。
- 新 HTML 只引用与该部署匹配的哈希资源。
- 已缓存未变化资源继续复用，发生变化的资源因新 URL 自动下载。

### 禁止状态

- 新 HTML 仍引用已删除或不匹配的旧资源。
- 旧 HTML 长期不验证，用户永远无法发现新哈希。
- 强制清空全部缓存，牺牲未变化资源的复用价值。

### 验收

1. 在旧部署中预热浏览器缓存，再发布同时含 HTML 和资源变化的新版本。
2. 重访页面并记录 HTML 验证、旧资源复用和新资源请求。
3. 检查页面没有混用不同部署的脚本、样式或内容。
