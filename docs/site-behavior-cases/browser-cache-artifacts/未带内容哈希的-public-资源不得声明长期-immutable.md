# 案例：未带内容哈希的 public 资源不得声明长期 immutable

### 场景

public 目录提供 favicon、清单、固定名称图片或其他可能原址更新的文件。

### 正确行为

- 没有内容寻址保证的稳定路径使用可重新验证或有限期限缓存。
- 文件原址更新后，浏览器能够在合理时间内获取新内容。
- 若确需长期 immutable，先把资源改为可靠的版本化或哈希地址。

### 禁止状态

- 因文件位于静态目录就统一设置一年 immutable。
- 原址替换资源后只能要求用户手动清缓存。
- 查询参数或时间戳随意变化，产生不可控缓存分裂。

### 验收

1. 枚举 public 输出并区分内容哈希与稳定名称资源。
2. 检查每类响应头符合其地址语义。
3. 原址更新测试资源，用已有缓存会话确认可获得新内容。
