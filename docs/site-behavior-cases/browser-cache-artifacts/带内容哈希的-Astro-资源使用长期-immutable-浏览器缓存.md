# 案例：带内容哈希的 /_astro/ 资源使用长期 immutable 浏览器缓存

### 场景

构建生成文件名包含内容哈希的脚本、样式、字体或图片，并通过 /_astro/ 路径提供。

### 正确行为

- 哈希变化即代表内容地址变化，因此响应可使用长期缓存和 immutable。
- HTML 更新后引用新的哈希 URL，旧资源可安全留在浏览器缓存中。
- 缓存规则只覆盖真正由内容寻址保证不可变的资源。

### 禁止状态

- 对哈希资源设置短缓存，导致每次访问无意义重新验证。
- 在同一哈希 URL 下替换内容，破坏 immutable 契约。
- 用宽泛路径规则误伤没有内容哈希的文件。

### 验收

1. 检查代表性脚本、样式、字体和图片的 URL 与 Cache-Control。
2. 内容不变时重复构建，确认地址稳定；内容改变时确认哈希和地址变化。
3. 用真实浏览器重访，验证哈希资源由本地缓存复用。
