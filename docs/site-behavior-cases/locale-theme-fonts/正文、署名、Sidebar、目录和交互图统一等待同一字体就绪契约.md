# 案例：正文、署名、Sidebar、目录和交互图统一等待同一字体就绪契约

### 场景

页面含多个会测量文字或依赖排版的消费者，字体可能延迟完成。

### 正确行为

- 所有几何消费者监听同一明确的字体 ready/degraded 状态。
- 目录计算、Sidebar 尺寸、Plotly 布局和 reveal 不使用各自随意的 timeout。
- 字体终态到达后，每个消费者至多执行一次必要校准。

### 禁止状态

- 正文稳定后，署名或目录仍单独闪烁。
- 多个组件各用不同延时反复测量。
- 字体失败后某些消费者永远等待。

### 验收

1. 延迟字体并记录各消费者开始测量和完成校准的时刻。
2. 确认它们依赖同一状态且失败路径同样结束。
3. 观察目录、Sidebar、署名与交互图是否分批跳动。
4. 多次站内导航，确认不会重复注册字体等待任务。
