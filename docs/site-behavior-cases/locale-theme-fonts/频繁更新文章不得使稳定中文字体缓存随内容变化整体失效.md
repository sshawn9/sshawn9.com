# 案例：频繁更新文章不得使稳定中文字体缓存随内容变化整体失效

### 场景

网站频繁新增中文正文、中文代码或公式字符并重新部署。

### 正确行为

- 中文正文使用版本稳定的 Unicode-range 分片，不按本站当前字符重建单一文件。
- 中文代码同样避免因每篇文章内容变化而让用户重新下载全部字体。
- 只有字体包或配置真正升级时，稳定资源 URL 才整体变化。

### 禁止状态

- 每次新增几个汉字就生成新的全站字体文件哈希。
- 为减少一次请求而让长期缓存频繁整体失效。
- 自定义子集扫描无关正文，造成代码字体无意义变化。

### 验收

1. 记录一次构建的字体资源 URL 和分片。
2. 只新增普通中文文章后重新构建并比较资源。
3. 再新增中文代码和公式，确认只影响应变化的资源。
4. 用浏览器缓存日志验证未变化资源不会重新下载。
